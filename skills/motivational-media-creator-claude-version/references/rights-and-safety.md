# 权利、事实与安全

## 证据账本

每个项目建一个账本（JSON 或 Markdown 表都行），时间线里的 `sources` 与 `claims` 从这里来。

### 素材 `sources`

| 字段 | 说明 |
|---|---|
| `id` | 如 `S01`；时间线里的 `shots`、`voice`、`music` 用它引用 |
| `kind` | `own-footage`、`third-party-footage`、`archival`、`interview`、`music`、`generated` |
| `rights` | 见下表 |
| `origin` | 来源描述或链接；不写本机私有路径 |
| `verified` | 原话是否已对着原始录音逐句核过 |

| `rights` | 含义 | 片子最高状态 |
|---|---|---|
| `owned` | 自己拍的、自己做的 | `publishable` |
| `licensed` | 有授权 | `publishable` |
| `permitted` | 本人或权利人书面同意 | `publishable` |
| `public-domain` | 公有领域 | `publishable` |
| `unclear` | 还没查 | `review` |
| `risk-accepted` | 用户本人明确说“风险自担”的二创素材 | `review` |

- 参考片只提供节奏与手法，参考≠授权。
- `risk-accepted` 只能来自用户在对话里的直接表态，按项目记录，不推广到别的项目。Skill 不把它当作清权。
- 合成旁白的音色要有使用权；不模仿任何真人的声音。

### 事实 `claims`

| `status` | 用法 |
|---|---|
| `verified` | 两个独立来源或一手来源 | 
| `single-source` | 只有一个来源：措辞要软（“据……”“约”），脚本会警告 |
| `disputed` | 来源互相矛盾：不进旁白，脚本会报错 |

- 数字、日期、比分、原话都进账本。原话保留原文与出处时间。
- 用户的记忆与事实不符时，按事实写，并告诉用户哪里不一样。

## 作者性

- 不编原话、不编内心独白、不编“那一刻他想到了……”。主人公自己讲过的，才能说。
- 不把复杂的经过压成一个干净的因果（“因为坚持所以成功”）。
- 保留反证：输的比赛、没回来的人、没有解决的事。

## 敏感题材

### 自杀与自伤

参考片里有主人公讲述自杀念头与一次接近自杀的经历。做同类题材时：

- 不出现方式、地点、速度等可模仿的细节；只说“最低的时候想过结束生命”这一级别。
- 讲出“求助”和“恢复是一段时间”，不讲“靠意志力战胜一切”。
- 片尾放求助信息：当地的心理援助或危机干预热线。号码每次从官方来源核实后再写，不凭记忆。
- 时间线 `sensitive.suicide_or_self_harm: true` 时，`safe_messaging_reviewed` 与 `help_card` 都要填，脚本才放行。

### 疾病、贫困、创伤

- 不把疾病或贫困归因于不够努力。
- 不展示可识别的旁人（家属、路人、未成年人）而未取得同意；必要时裁切或打码。

## 语气边界

参考片里常见三种腔调，本 Skill 不沿用：

- **羞辱观众**：“你们大多数人不会成功，因为……”。改成对观众的邀请，不贬低。
- **歌颂透支**：不睡觉、不过节、不过生日当美德。
- **承诺结果**：“你一定能成功”。只讲主人公做了什么、发生了什么。

用户明确要求某种更强硬的语气时，可以调整措辞强度，但上面三条的底线不变。
