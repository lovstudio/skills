# 交接范围与隐私

决定“什么出包、什么不出包”。默认规则先保护交出方，用户明确要求再放宽，并在交接文档的“不在交接包里的东西”一节写清。

## 默认带走

| 类别 | 说明 |
| --- | --- |
| 源工程 | 代码、配置、锁文件、工具脚本；去掉依赖树和编译产物 |
| 运行所需素材 | 渲染或构建时会读取的全部文件（片段、音频、字体、贴图、数据）|
| 切换状态所需的快照 | 版本快照、旁白或配置的备份、恢复步骤，以及恢复步骤会读取的原始文件 |
| 生成物的计划与记录 | AI 生成计划、每次生成的元数据、费用账本 |
| 最新成品 | 当前版本和仍可能回退的版本的成品，加全部版本说明 |
| 对方提供的材料 | 脚本、素材、界面截图、品牌文件、反馈文档 |
| 需求与决定记录 | 已整理的群记录、会议纪要中与制作有关的部分 |
| 质检与验收报告 | 文本报告和少量关键对照图，不带逐帧抽帧 |

## 默认不带

| 类别 | 原因与处理 |
| --- | --- |
| 合同、报价、付款、发票、合作方之间的分成与结算 | 商务信息。接手方需要知道的交付范围，在交接文档里用一句话说明归属 |
| 交出方的私人笔记、项目总览、个人复盘 | 往往混有商务、关系和个人判断。改写一份交接用的现状说明 |
| 联系人邮箱、电话、私聊记录、微信号、群 ID | 个人信息。交接文档只写角色和群名，需要联系谁在群里联系 |
| 交出方的账号、密钥、钥匙串条目、`.env` | 接手方用自己的；文档列出环境变量名和服务 |
| 被否掉的方向、废弃分支 | 与后续工作无关，容易误导。在文档里一句话说明它存在过 |
| 渲染缓存、预览缓存、依赖树（`node_modules`、虚拟环境）| 可重新生成；文档写清怎么装、怎么生成 |
| 交出方本机编译的二进制 | 换机器不能用；保留源码，首次运行再编译 |
| 交出方自有账号用的内容（个人频道的稿子、个人风格的拆解）| 与本项目交付无关 |

关系不清时（例如不确定接手方是不是合作方的人），按默认值出包，汇报时列出被排除的内容。

## 读扫描报告

- **疑似密钥**：常见误报是钥匙串服务名、示例占位、文档里的变量名。逐条打开确认；真密钥要回源工程删掉或移到环境变量，不能只在包里删。
- **个人信息**：链接参数里的长数字会被当成手机号；接口文档的示例数据里也常有号码。只有真实联系人的信息需要处理。
- **本机路径**：运行时会读取的（配置、脚本里的路径）回源工程改成相对路径；只出现在日志、报告、任务记录里的，打包后用 `handover_sanitize.py` 遮盖。
- **可重新生成的目录**：按名称判断，只是候选。`build/`、`cache/` 下常常放着快照或原始素材，逐个确认。

## 遮盖路径的边界

- 只改文本类生成物：`.json .jsonl .txt .md .tsv .csv .log .src .yaml .yml`。
- 运行时读取的文件（`package.json`、各类配置、源码、锁文件）不改；预演里出现 `FUNCTIONAL-LOOKING` 就停下处理源头。
- 应用后对比源工程：改动只落在报告、任务记录、校验和这类文件上。
- 字体或素材来源记录里的本机路径属于元数据，可以遮盖，但许可信息保留。

## 交接文档里的人和事

- 写角色、职责和在本项目里管什么；不写联系方式和私下评价。
- 引用对方的话写明时间和提出人，原意不改；推断写明是推断。
- 商务进度（付款、开票）不写进交接文档；需要接手方配合的商务事项，写“由交出方处理”。
