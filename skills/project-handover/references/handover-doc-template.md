# 交接文档模板

三份文件放在交接包根目录。写给“只拿到这个包、没参加过之前任何沟通”的接手方和他的 Agent。所有路径都是包内相对路径；写完用 `handover_manifest.py check-refs` 核对。

## HANDOVER.md

按下面的顺序写；某节确实没有内容时写“无”，不要删掉标题，接手方的 Agent 会按标题找。

```markdown
# <项目名> 交接文档

交接日期：YYYY-MM-DD。交出方：<称呼>。本文写给接手的人和接手方的 Agent：人先读第 0、2、3 节，Agent 先读 AGENTS.md。
本文事实截至 <日期 时间>。<哪些渠道没读到> 涉及的地方标了“看不到”。

## 0. 三十秒概况
做什么、规格、节点；当前状态（哪个版本）；对方最后看到哪一版；眼下最要紧的三件事。

## 1. 对方、角色与沟通
### 1.1 群与人         群名与用途；人：角色、管什么（不写联系方式）
### 1.2 对方的固定偏好  反复出现过的要求，每条带提出人和日期
### 1.3 对外门禁        什么必须对方确认后才能发

## 2. 版本与分支
表：版本、日期、差别、文件位置。当前工程处于哪个状态，怎么切换（指向恢复步骤），切换的副作用。

## 3. 待办（按优先级）
### 3.1 最新一轮意见    逐条：原意、推断位置、备注（依赖什么、谁要确认）
### 3.2 其他未完成事项  脚本、数据口径、遗留问题、没做的交付物、不在交接范围内的工作

## 4. 关键技术决定
每个影响后续做法的决定：怎么来的（谁、何时）、现状、经验与坑、建议做法。

## 5. 工程地图
目录树，每个目录一句话。

## 6. 环境与账号
表：用途、需要什么（版本、环境变量名、账号来源）。第三方服务的计费与限额坑。许可要求。

## 7. 常用操作
第一次打开、预览与构建、改内容的工具链、生成素材、费用账本。每条命令写在哪个目录执行。

## 8. 交付惯例
命名、版本号、每版要写的说明、回读、状态用词。

## 9. 不在交接包里的东西
表：内容、原因。

## 10. 已知缺口
没读到的渠道、推断的地方、未验证的环节。

## 11. 交接验收记录
表：项目、结果（清单、敏感信息扫描、安装与类型检查、关键工具、完整重建与比对、验收中修正的问题）。
```

写作要点：

- 第 0 节能独立读懂；“眼下最要紧”写成可执行的事，不写空泛提醒。
- 最新意见要逐条列，保留原意；截图看不到时写明“对应位置为推断，动手前核对”。
- 每个“为什么这样做”的决定都写来源，接手方需要据此判断能不能改。
- 命令都要在验收里实际跑过；没跑过的标“未验证”。

## AGENTS.md（接手方 Agent 的工作约定）

从交出方的项目约定改编：

- 保留：事实来源优先级、对外门禁、作品的讲法与风格约束、红线、制作规范（命名、目录、版本与说明、回读）、费用记账、状态用词。
- 去掉：只适用于交出方个人账号或个人内容的规则；指向交出方本机文件、私人参考资料或私人工具的引用（改写成规则本身）。
- 新增：开始任务前先读 HANDOVER.md 的哪几节；不得删除的快照；花钱前先估算并告知负责人；代表制作方对外发消息前先给负责人看草稿；群里不谈费用。

## CLAUDE.md

一行：本项目的 Agent 工作约定写在同目录的 `AGENTS.md`，开始任务前先读它和 `HANDOVER.md`。用普通文件，不用符号链接。
