# 转载稿编辑增量

## 目标

发布方增量解释“为什么由我们转发、与读者有什么关系、我们真实在意什么”。它应明显小于来源正文，不冒充来源作者，也不借合作方名义为发布方背书。

## 稳定结构

1. `opening-hero`：可选，独立 `4:3` 正文首图；
2. `publisher-intro`：一到三段，提供公开、可证实的转发动机；
3. `source-attribution`：来源账号、原文标题和完整 URL；
4. `source-body`：冻结原文；
5. `publisher-outro`：一到两段真实判断或行动邀请；
6. `brand-endcap`：从 Profile 读取的稳定出版组件。

每个增量区块使用唯一 `data-repost-block` 值，来源正文另用 `data-repost-source="true"`，避免编辑或回读时误选。

## 写作门禁

- 内部聊天中的初步议题、未官宣嘉宾、价格、时间安排、联系人和审核状态默认不公开。
- 可以写“我会在现场”只在用户身份和公开参会事实已确认时；不能从邀约草案推断已官宣角色。
- 不写“重磅、必看、顶级、强强联合”等无证据套话。
- 不把合作方长名单重新摘要成可能漏项的二手版本；原文已经完整表达时，让来源正文自己说话。
- 转载标题可保留原题，也可从发布方身份重拟；不得让读者误以为来源账号就是当前发布账号。
- 作者元数据优先保留来源账号；发布方评论通过结构而非抢占署名区分。

## 品牌增量

只使用 Profile 允许公开的发布主体、品牌事实和主链接。尾注保持稳定、低视觉权重；产品与原文没有直接关系时不枚举。合作方 Logo 与发布方 Logo 分层，任何 Logo 都只使用官方资产。
