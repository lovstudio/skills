# 修改与同步边界

命名清单可供修改流程消费；结构校验通过不代表已经改好。

## 本地修改

1. 解析 canonical source 与软链接，读 Git 状态，记录旧值，保留其他未提交工作。
2. 只改实际公开名称字段：catalog 的 `name_zh` / `display_name`、已有 manifest
   显示字段、`agents/openai.yaml` 界面名称及 SKILL/README/Card 对应标题。
3. `name`、`runtime_name`、slug、仓库、目录、Profile key 属于兼容合同。
   禁止全文替换；代码围栏中的 H1、引用、历史案例和 CHANGELOG 不是当前标题。
4. 按实际结构处理，不假定字段位于第二行；使用拒绝重复键的 YAML 解析器。
   验证幂等性，第二次运行不再产生改动。
5. 由优化器遵守项目版本策略，精确暂存本任务内容，验证安装副本的目标与显示名。

## 官网与渠道

发布是单独的已授权阶段，交给发布器。名称调整不自动授权公开新 Skill、改价格、
重打付费包、解密源文件或改权限。

目录同步后，等自动同步和 CI 完成，再回读源码、目录、各语言页面与安装结果。
首屏可能分页，不能以首屏卡片证明整组已更新；CI 从源仓库重建镜像后也要检查旧名
没有恢复。分别记录本地已修改、目录已提交、页面已验证、安装已验证。
历史任务链接仅提供命名依据，不能复用其中的发布、删除或下架动作。
