# 新选题创作与验收协议

## 输入与冲突顺序

用户事实、权利和安全边界优先于风格。用户指定片长/画幅优先于样本平均值。画像是可参考的条件规则，不是作者本人、医学知识库或“爆款保证”。

使用 brief.schema.json；提供明确 topic、audience、duration_seconds、scenario_type、facts、actor_voice、available_assets 和 cta。事实必须有来源；演示场景标记 fictional_demo，不能写成作者亲历。

## 内容生成

1. 写出本片要解释的真实矛盾，区分可观察行为、观众直觉、可能机制、替代解释和选择。
2. 选择画像中的一个叙事变体。解释所需的篇幅决定段落数量，不强行三段式。
3. 先列 beat，再写口播。概念首次出现用生活语言解释，不堆术语或潜意识断言。
4. 设问、对照、角色代入和类比服务推理；不为模仿而堆“你发现了吗”“底层”“本质”。
5. 结尾回到观众能做的观察/行动或保留的问题；服务 CTA 需用户明确给出身份、服务与合法承诺。

原视频的“我帮助过很多来访”“我是心理咨询师”不是新作者的事实，不能照搬。不得编造名人私生活、童年或动机。引用来源中的心理推断时必须说明是原作者的解释，不是临床结论。

## 声画时间线

时间使用秒、左闭右开；片段从0连续覆盖目标时长，每段正时长。字幕来自最终口播原文，不是摘要，保持一至两行、短分句，暖色只强调必要词。字幕、配音、画外音和素材插入共用同一权威时间线。

先选自己的出镜/已授权音色。动作指令描述机位、景别、手势、停顿、重音和证据插入动机，不描述如何复制原作者身份。证据画面应与当前论述有关；无授权时列为待拍摄/待授权，不假装素材已就绪。

主讲画面优先固定近景与清楚的面光。不能把室内布景、衣服、原作者脸型当风格硬规则。竖版、横版章节栏、奶油色卡片是不同布局，不相互硬套。

## 输出与状态

- facts-ledger.json：事实、解释、虚构标识、禁止编造和未知。
- script.md：完整口播及必要表演提示。
- edit-plan.json：唯一权威时间线，符合 edit-plan.schema.json。
- storyboard.json：从 edit-plan.json 派生镜头/素材需求，禁止另建矛盾时间码。
- style-review.json：结构校验、语义审阅、差异和未验证项。

prepared、validated、rendered_review、human_approved、published 是不同状态。没有实际编码文件时只能说脚本/制作方案完成，不能说视频已生成。自动通过不能冒充人类盲评、听审或用户认可。

## 验收顺序

先跑 profile 与 plan Schema/交叉引用检查，再核对论点来源、因果压缩、反例存活、结尾过度解决、读者推理空间、段落不对称、作者选择。之后才看口头表达是否接近参考。

定量与定性分开：原片文本密度和响度是测量，模型“听起来坚定”的判断是解释。模型自评 high 不是经校准的置信概率。记录不一致，不把所有差异折叠成一个虚构相似度分数。

## 声音与权利

原片部分 True Peak 高于0dBTP，不复现此缺陷。新成片默认参考-16 LUFS-I、True Peak不高于-1dBTP，平台明确要求优先。无已授权音乐时不添加音乐；不得用程序合成的占位配乐冒充来源音乐。参考截图和音频用于本地分析，不自动授予发布使用权。
