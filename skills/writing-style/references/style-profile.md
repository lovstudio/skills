# v2 文风画像

## Evidence Basis

本画像来自用户授权提供的 2026-08-25 分析结果。语料覆盖 19 篇文章，其中 16 篇
回读归档 Markdown，3 篇回读正文缓存；清理图片、表格边框等结构后约 12.46 万
字元、2,846 个句子、2,559 个行段。

题材覆盖技术与产品深度稿、创业与方法论复盘、个人叙事。以下规则优先保留跨题材
稳定特征；只在单一题材出现的表现必须按模式选择，不能机械复制。

原始文章不随 Skill 分发。本文件只保存用户授权的聚合画像与行为规则。

2026-08-26 的一次用户手工修订被作为直接校准事件：它不增加 19 篇语料的统计口径，
只用于补充“并列对象的分段、承重句加粗、技术枚举列表化、停止重复解释”等编辑决策。

## Style DNA

工程实战驱动的创业者第一人称深度稿：以真实行动建立可信度，以结构化框架输出
认知，以口语短句和个人情绪避免报告腔，最终把工具、产品与商业问题收束到人的
判断、行动、自由和价值。

高频材料组合（用于识别，不作为逐篇配额）：

> 现场经历 × 工程细节 × 概念辨析 × 强判断 × 人的处境

这些元素可以单独出现，也可以完全不出现。真正稳定的是作者如何取舍证据、暴露
限制和承担判断，不是文章必须沿同一条路线完成“人的回归”。

## Stable Features

### Sentence Rhythm

- 平均句长约 39.1 字。
- 短句（少于 15 字）约 19.8%，中句约 31.7%，长句约 48.6%。
- 长句负责背景、条件、转折、因果和解释，短句负责判决、停顿和转向。
- 典型节奏是铺陈长句 → 两三个短句 → 一条有证据支撑的结论。
- 逗号、冒号和破折号承担主要停顿；问号用于启动问题。
- 感叹号和省略号总体克制，只在真实情绪高点出现。
- 碎片句可以独立成段，但必须承担语气或逻辑作用。

这些数字是诊断参照，不是逐篇 KPI。短稿、演讲与个人随笔允许自然偏离。

### Paragraph Structure

- 一句段约占 79.9%，平均每段约 1.11 句。
- 一句一段的作用是移动焦点、制造留白和让判断落地，不是把标点机械替换成换行。
- 当三到五个并列对象各自承担一项鲜明差异时，连续的一句段比一个塞满分号的长段
  更接近作者节奏：每段只推进一个对象，读者自然看见对照。
- 长文常见导语 / 目录 → 编号章节 → 结论型小标题 → 表格或清单 → 写在最后。
- 三种稳定开头：
  1. 具体时间与亲历事件；
  2. 反常识问题或矛盾；
  3. 已验证的结果或数字。
- 概念或技术稿常用定义 → 区分 → 拆解；时间叙事、现场记录和并列评述不必套用。
- 多个同级章节完成后，如果需要压缩差异，单独设置“汇总表”等真实小标题；不要让
  表格像正文中途突然掉下来的附件。
- 结尾通常不做普通摘要；可以落在人的选择，也可以停在事实、动作、疑问、代价或
  未解决处。不得为了复现画像而统一抬升价值。

### Vocabulary

- 中文口语、工程术语和必要的英文原词自然混搭。
- 英文用于保留 AI、Agent、Skill、Context、Harness、IDE、OPC、Vibe Coding、
  commit、fork、session 等概念边界，不用于装饰。
- 偏爱行动动词：跑通、复盘、拆解、回滚、发布、验证、维护、迭代、重做、接入、
  交付。
- 年份、时长、金额、比例、项目数、版本号直接进入标题和论证。
- “但、所以、其实、不是、而是”用于持续纠偏和重新定义。样本中“但”约 301 次、
  “不是”约 177 次、“而是”约 104 次。
- 形容词服从判断。技术稿更常使用稳健、可靠、干净、脆弱、简单粗暴等可解释词。
- “说实话”“真地”“这件事”“没那么简单”“我越来越相信”可自然出现，但不是
  每篇必备签名。
- 赋能、生态闭环、颠覆性创新等公关词不能直接充当结论。

### Narrative Voice

- 第一人称是主轴。样本中“我”约出现 1,007 次。
- 第二人称用于复现场景、提出问题和给出建议。样本中“你”约出现 351 次。
- 作者位置是“先行一步的同行者”：有专业判断，也公开失败、代价、误判和局限。
- 不躲在机构口吻后面，也不从讲台俯视读者。
- 工程师、创业者、独立开发者、产品实践者、活动组织者和旅行者等身份只能在
  输入事实支持时使用。

### Emotional Register

- 基调高能、坦率、带锋芒，但不是持续亢奋。
- 技术稿以克制分析为主，关键处才亮出强判断；个人稿更柔软、更自省。
- 常见弧线是困惑或受挫 → 亲自试验 → 形成框架 → 抬升为信念。
- 时间、金钱、失败、现场人物和产品证据承载情绪，少用空喊。
- “我错了”“后来我才发现”只有在输入存在真实反转时才能使用。

### Argumentation

- 问题导向、结论前置。标题或导语先给矛盾与方向，再用材料证明。
- 第一层证据是亲历，第二层是框架，第三层是数据、案例和外部资料。
- 擅长处理 X 不是什么、X 与 Y 的区别、能做什么 / 不能做什么、收益 / 代价。
- 历史样本中常见但非必选的推理链：
  1. 真实痛点或现场；
  2. 对既有说法提出不满；
  3. 定义概念并区分相邻概念；
  4. 按时间或维度展开证据；
  5. 承认代价、边界与未解问题；
  6. 给出可行动的判断；
  7. 在材料支持时回到人的选择或创作价值。

### Rhetoric

- 对照与否定重定义是主要骨架，例如“不是 X，而是 Y”。
- 三段或四段排比把抽象价值落成节奏。
- 设问开门，反问加压，答案随后由案例展开。
- 比喻来自工程与生活现场，使抽象技术可见。
- 加粗句承担可传播判断，但前面必须有事实铺垫。
- 加粗也承担信息层级：长稿可以分别标出工作定义、核心论点和最终判断，但不能把
  每个小节都包装成金句。
- 有性格的标题可以直接承担口语、调侃和比喻。正文只需用事实把它兑现，不要紧跟
  一句解释“这只是玩笑”或自我审查式降温。
- 英文口号后应有中文解释，把借来的概念变成作者自己的判断。

### Editorial Compression

- 已经清楚声明一次的版本、样本、来源或不确定性，不在后文重复辩护。
- 删除解释标题、解释幽默、解释自己为什么这样写的元话语，让证据自己完成定调。
- 四项以上相互独立、结构平行的具体机制或例子，优先列表化；因果链和判断仍用段落。
- 文尾身份介绍只保留名称、网址、正在做什么和为什么值得继续关注，不用“不是 X、
  不是 Y”式防御替品牌证明自己。
- “停止解释”不等于删除事实限定。只在个人判断层收紧语气，不把有限样本升级为
  市场排名、行业共识或永久结论。
- 区分“作者经历”和“协作过程”：产品失败、实验返工可以成为文章事实；聊天里的
  第几稿、用户如何批评、Agent 如何修改默认只是 production context。面向公众的
  成品不得让冷读者靠猜测补齐“前一版”“这次”“刚才”的先行词。

## Occasional Features

只按题材和真实情绪选用：

- 产品快评可以使用连续短句、强烈好恶、自嘲和少量粗口，但必须有真实 case。
- 情绪高点可以使用重复句、空格断字或轻微夸张，研究稿中禁用。
- 个人与旅行随笔可以减少小标题，靠场景、人物和时间回望推进。
- 演讲与招募稿可以直接呼叫“大家 / 朋友”，结尾允许行动号召。
- 技术深度稿可以使用目录、时间线、对照表、脚注和边界声明。

## Anti-Parody Rules

- 不按配额插入“真地”“共勉”“我错了”或英文术语。
- 不把每句话都切成一句段。
- 不把所有标题都改成数字和感叹号。
- 不为空洞观点补造凌晨、办公室、债务、投资人、旅行或产品现场。
- 不把强判断写成羞辱，也不把坦率写成持续粗口。
- 不在一个有辨识度的标题后立刻解释梗、道歉或把语气重新磨平。
- 不重复已经交代过的事实边界，只为显得严谨而把同一免责声明写两遍。
- 不为了像而复制原文句子；复现的是决策方式、论证方法和节奏。
- 不把“现场 → 定义 → 拆解 → 人的价值”复制成所有题材的统一大纲。
- 不把文章里可由读者自行得到的意义全部解释完。
- 不把审稿对话写进成品，不用“我前一版写错了”“按你的要求重写”向陌生读者开场。

## Forbidden Patterns

- “随着时代发展”“在这个日新月异的时代”等无信息开场。
- 把“赋能、闭环、生态、颠覆”当作无需证明的结论。
- 全程第三人称、没有作者位置的机构报告。
- 只给观点，不交代亲历、数据、案例或可验证细节。
- 所有段落都是等长的三五句。
- 滥用感叹号、emoji、鸡汤金句和华丽形容词。
- 翻译掉所有英文术语，或无解释地堆叠缩写。
- 回避失败、代价、边界和判断变化。
- 使用“综上所述”完成普通摘要式收尾。

## Calibration Checklist

1. 标题是否含有真实冲突、结果、数字或明确问题？
2. 开头 300 字内是否出现作者现场、痛点或核心结论？
3. 是否先定义概念，再区分相邻概念与适用边界？
4. 每个主要章节是否至少有一项事实、案例、数据或亲历支撑？
5. 长句解释、短句落锤的节奏是否成立？
6. 是否保留诚实的“我”，并用“你 / 大家”建立平等对话？
7. 是否承认真实存在的代价、失败、不确定性或认知反转？
8. 结尾是否完成本篇工作，并避免重复总结、强行升华或无依据 CTA？
9. 同一事实边界是否只声明一次，同时没有把有限证据写成绝对事实？
10. 并列对象、技术枚举、汇总表和承重句是否各自使用了合适的视觉层级？
11. 是否删掉了标题后的解释梗、重复免责声明和无必要的防御性品牌自述？
12. 标题与开头 300 字脱离会话后是否仍能独立成立，所有版本与指代是否有可见先行词？
