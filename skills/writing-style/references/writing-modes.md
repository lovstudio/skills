# Writing Modes

选择一个主模式，再按交付长度缩放。模式决定结构和情绪，不改变事实边界。

## 技术深度

适用：AI、Agent、Skill、Context、开发工具、工程实践与架构判断。

- 开头：真实实验、故障、上线结果或一个被反复误解的工程问题。
- 结构：定义 → 相邻概念区分 → 方案 / 时间线 → 证据 → 边界。
- 证据：版本、命令、耗时、成本、错误、对照、来源链接。
- 温度：整体克制，结论处有锋芒。
- 允许：目录、表格、脚注、代码与明确的不能做什么。
- 编排：多个产品、方案或实现并列时，先让每个对象拥有独立判断，再用汇总表压缩；
  四项以上同级技术例子优先列表化。
- 节奏：开头可以用连续一句段建立对象差异；定义、核心论点和最终判断可少量加粗。
- 收束：事实边界只交代一次，不反复解释标题、幽默或写作动机。
- Benchmark：排名、分数与雷达图之前，先公开系统版本、输入和对照、实际执行与评分
  Prompt、维度来源与适用样本、换算权重、单样本算分链和可执行复现路径；完整文件可
  放附件，但正文必须让读者理解“这个分从哪里来”。下载包尚未公开时如实标记。
- Benchmark 标题：使用“调研对象、测试方法、Prompt、评价指标、评分方法、评分示例、
  复现方法、测试结果、局限性、结论”等论文式描述标题；不要把每一节包装成反问、
  情绪判断或传播金句。
- 禁止：用情绪替代验证，或把工具体验写成普遍规律。
- 冷启动：公开技术稿从实验对象、结果、数字或问题进入，不从旧稿轮次、审稿意见或
  “我又重写了一遍”进入。

## 创业复盘

适用：产品发布、融资、OPC、收入、失败、组织和个人工作流。

- 开头：时间、金额、数量、关键选择或失败现场。
- 结构：当时怎么判断 → 做了什么 → 结果与代价 → 判断如何变化 → 方法。
- 证据：利益关系、投入、损失、机会成本与真实转折。
- 温度：坦率、自省，不贩卖成功学。
- 允许：编号原则和行动清单。
- 禁止：事后诸葛亮，或把个案包装成唯一答案。

## 产品实测 / 快评

适用：真实使用过的产品、模型、工具或功能。

- 开头：一项反直觉结果、明确数字或强烈体验。
- 结构：预期 → 实际操作 → case → 好恶判断 → 适用边界。
- 证据：版本、设置、任务、截图、结果和失败尝试。
- 温度：五种模式里最锋利，可用更密集的一句段。
- 允许：自嘲、短句反复和少量粗口。
- 禁止：没有实测就写“我试了”，或把偶发结果当稳定结论。

## 个人 / 旅行随笔

适用：年龄、旅行、人物、选择、关系与创业情绪。

- 开头：地点、人物、动作、物件或时间回望。
- 结构：按场景或时间推进，少用方法论目录。
- 证据：感官细节、具体对话、路程、物件与当时选择。
- 温度：更柔软、更舒展，允许长句延伸。
- 允许：末段用具象意象完成抬升。
- 禁止：强行总结成商业方法，或堆叠抽象抒情词。

## 演讲 / 招募

适用：公开演讲、活动介绍、招募信、发布会讲稿。

- 开头：直接呼叫现场，尽快说明为何此刻要谈这件事。
- 结构：共同问题 → 亲历与证据 → 主张 → 对听众的具体邀请。
- 证据：现场背景、过往行动、可验证结果与参与边界。
- 温度：比文章更直接，但不喊空口号。
- 允许：大家、朋友、如果你，以及明确 CTA。
- 禁止：只有愿景，没有谁在何时做什么。

## Length Adaptation

### 标题

只保留一个冲突、结果、数字或问题。不能为了“像”而同时塞入所有元素。

### 短帖

一个现场或事实、一个判断、一个收束。通常不加目录和多级标题。

### 中篇

使用两到四个结论型小标题。每节至少有一项证据。

### 长文

当内容确实有三个以上稳定章节时再加目录。优先按时间、问题、维度或方案组织，
不混用多个分类轴。

## Mixed Requests

若用户同时要求两种模式，选一个主模式、一个辅温度。例如：

- “技术深度 + 个人感受”：技术深度负责结构，个人随笔只影响开头和结尾温度。
- “创业复盘 + 快评”：创业复盘负责证据链，快评只提高短句与判断强度。
- “演讲 + 技术深度”：技术深度负责准确性，演讲模式负责口播节奏与 CTA。

不要按章节轮流换人格。
