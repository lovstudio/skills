# 视频发布器（微信视频号 / Bilibili）

![Version](https://img.shields.io/badge/version-0.9.1-CC785C)

通过已登录的创作者后台网页预检、上传并发布本地视频，支持离线文案预检、上传与表单并行、完整元数据门禁、
封面安全区验收、**提交前由用户确认终稿**、保存草稿、定时发布和发布状态回读。

由 `lov-publish-wechat-channels` 升级而来，旧名仍可触发但已 deprecated。

未指定平台时，默认依次发布到**微信视频号 → B 站**，不再询问发布目的地。明确指定平台或
顺序时按当次要求执行；先完成视频号动作并回读列表状态，再进入 B 站。前一平台阻塞时先
处理具体问题，不自行跳过。已给出条目链接或 BV 号的状态查询只检查对应条目。

## 适用场景

- 发布微信视频号或 B 站视频
- 保存草稿、安排定时发布
- 回读内容列表中的审核、转码或发布状态
- 按用户已确认的标题、描述、话题/标签、封面完成逐项核验
- B 站发布后通过标签专用接口与公开页节点回读 tags，避免把简介里没有 `#标签` 误判为丢失
- B 站存在已核验章节时，把最终成片时间轴写入简介，供观众点击跳转
- 逐个检查页面上实际存在的封面槽位的裁切安全区
- 发布后按用户要求保留列表页面用于 review

## 两个平台的差别

| | 微信视频号 | Bilibili |
| --- | --- | --- |
| 硬限制 | 4 GiB / 2 小时 | 16 GB / 10 小时 |
| 标题 | 短标题 ≤16 字，禁用逗号 | 稿件标题 ≤80 字 |
| 描述 | 未观测到硬上限 | 简介 ≤2000 字 |
| 话题/标签 | 话题必须由平台按钮生成 | 标签 ≤10 个，部分名字是话题专用 |
| 合集 | ≤10 字，**创建后不可修改** | 创建 20 字 / 编辑 50 字，可改名 |
| 封面槽 | 1 个（3:4） | 2 个独立槽（4:3 与 **16:9**） |
| 发布后 | 不可撤改 | 可编辑，但改完要重新点「立即投稿」 |
| 前端 | wujie 微前端 + shadow DOM | 普通 Vue 应用 |

所有脚本都必须显式传 `--platform`——拿一边的默认值去卡另一边只会得到假结论。

## 使用前提

- 运行时需要 `ego-browser`，并在同一账号登录态的 task space 中访问目标平台。
- 发布或保存草稿时准备本地视频绝对路径。
- 媒体预检只读调用 `ffprobe`，不转码、不覆盖源视频。
- 交接语音默认优先火山 TTS：配置 `VOLC_APPID` / `VOLC_TOKEN`；未配置时自动降级为 macOS `say`。

## 安装

```bash
npx skills add lovstudio/media-publisher-skill -g -y
```

## 关键行为

技能在开页前先冻结成片与封面的绝对路径。上传启动后，只要字段区稳定，就立即填标题、简介、
标签、合集和声明，不等视频处理完才开始。封面编辑器被上传状态锁定时，其他字段仍继续；确需人工操作时，
同时给出可点击的精确文件路径、系统通知和火山 TTS 指令。

技能会在写入前回读每个字段的真实值（`value` / `checked` / 标签节点）、每个封面槽位，并输出
提交前字段表。B 站双封面按 `#editor_4_3` / `#editor_16_9` canvas wrapper 的激活状态上传，
不把右侧效果预览按钮误认成编辑槽；任一必填字段未持久化或封面未通过时不会提交。

描述按“平台页面用户手改 → 当前会话逐字文本 → 项目批准稿 → 自动草稿”的顺序取值。检测到
用户已经在页面修改后会冻结全文；上传封面、选合集或勾原创等后续动作不得重建或润色描述，
并在每次操作后逐字回读，防止旧草稿覆盖用户终稿。

知识技巧短视频默认使用“真实痛点问句 → 能力承诺问句 → 5–10 个精准关键词”，不再强制系列
介绍、内容摘要或客套收尾。迁移到 B 站时保留同一钩子核心，把视频号话题迁移到标签字段；
存在批准章节时只在钩子后追加完整时间轴。

用户接管页面、手动修改并表示已经发布后，Skill 不会重新点击提交或恢复旧字段：实际发布文本
成为最高优先级来源，后续只做内容列表回读。用户报告与平台验证分开记录，列表未验证前不会
把状态误写为 `published`。

B 站若已有最终成片的批准章节，简介必须逐行包含全部 `MM:SS 章节名`（超过一小时用
`HH:MM:SS`），并逐条回读，确保平台能识别为可点击跳转。时间码只取最终成片时间轴，不从
源录屏或旧版本复制；用户手改简介已冻结时，只做经用户明确要求的最小追加。

**提交前一定停下来等你确认终稿**：字段表全项通过后进入 `awaiting_confirmation`，发系统通知与
语音播报，把终稿——尤其是被平台改写过的字段（短标题超限被改写、位置被自动带入、标签被
「话题专用」拒掉后换了同义词、封面槽位数与预期不一致）——交给你过目，得到明确同意才提交。
会话开头的「发吧」只授权启动流程，不替代终稿确认。草稿与定时发布不需要这一步。

文案约束能离线判定的先离线挡掉，不等页面来拒。两条最容易踩的：视频号合集 ≤10 字且创建后
不可修改，超长要重新起名而不是截断照建；B 站的 16:9 封面槽是列表、空间和信息流真正用的
那个，只传 4:3 等于没传，唯一可信验证是投稿后拉公开接口读 `pic`。

提交后重新加载内容列表；显示「审核中」「转码中」等处理中状态时保留平台原文并报告
`platform_pending`，只有列表明确显示已发布才报告 `published`。B 站还要从公开 `view` 接口逐字
回读 `title / desc`、目视核对 `pic`，tags 另查 `/x/tag/archive/tags` 并按名称集合验收。
