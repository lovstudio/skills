# 手机可读性标准

本文件定义 1080 画布下的硬指标。`scripts/infographic_cli.py audit` 直接按这些数字判定，
修改任何一条都要同时更新脚本常量与本文档。

## 画布与比例

| 比例 | 像素 | 适用场景 |
| --- | --- | --- |
| `long`（默认） | 1080×自适应 | 默认形态：一张卡，高度跟着内容走；下限 1.2× 宽，上限三个 `3:4` 屏（4320px） |
| `3:4` | 1080×1440 | 渠道强制固定比例时：微信图文内嵌、朋友圈、小红书笔记 |
| `4:5` | 1080×1350 | 信息流占位更高的场景 |
| `9:16` | 1080×1920 | 全屏故事卡、视频封面 |
| `1:1` | 1080×1080 | 九宫格、头像位、列表缩略图 |

宽度恒定为 1080，导出倍数默认 2×（2160 宽），需要额外放大时用 `--scale 3`。
`long` 不需要为了凑高度而加留白，也不需要因为内容多就先拆卡；超出 4320px 才必须删减或拆卡，
`audit` 以 `long_height` 警告记录这条上限。

## 字号下限与真实视口

1080 画布在 390pt 宽的手机上显示时缩放约 0.36。换算后：

| 角色 | 画布 px | 等效显示 | 用途 |
| --- | --- | --- | --- |
| `title` | ≥ 72 | ≈ 26pt | 这张卡的唯一标题 |
| `value` | ≥ 96 | ≈ 35pt | 关键数字 |
| `claim` | ≥ 50 | ≈ 18pt | 结论句 |
| `body` | ≥ 36 | ≈ 13pt | 正文与依据 |
| `label` | ≥ 30 | ≈ 11pt | 分组标签、序号 |
| `note` / `source` | ≥ 26 | ≈ 9pt | 口径、限定、来源 |

低于 26px 的文字在手机上会明显吃力，脚本按 critical 处理。

行高经验值：中文字体栈（PingFang SC、Hiragino Sans GB）的内容区约为 1.4em。
行高低于该值时字形盒会溢出自身盒模型，`audit` 记为 `glyph_overflow` 警告；
标题实测 1.32 足够，132px 的关键数字需要 1.4。

## 行宽

按中文字符当量计数（拉丁字符按 0.55）：

| 角色 | 每行上限 |
| --- | --- |
| `title` | 14 |
| `claim` | 20 |
| `body` | 24 |
| `label` | 20 |
| `note` | 28 |
| `source` | 34 |

超过上限说明信息密度已经不适合手机阅读；正确做法是拆句或拆卡，而不是缩小字号。

## 对比度

- 正文（< 40px）：≥ 4.5:1。
- 大字（≥ 40px）：≥ 3:1。
- 品牌强调色直接用在文字上通常不达标（示例品牌橙 #EB6637 在纸色上只有 2.95:1）。
  强调色只用于线条、色块与图形；文字强调色使用 `accent_ink`。

## 安全区

- 左右边距 88px（≈ 32pt），上下边距 96px（≈ 35pt）。
- 内容不得越过安全区；排版超出画布或挤压到边缘都按 critical 处理。
- 底部页脚固定包含：品牌 Logo、署名与 `n/N` 页码。

## 一屏信息量

- 一张卡只讲一个结论，`data-claim` 有且仅有一个。
- 证据块最多 3 个，步骤最多 5 步，清单最多 5 条。
- 可见文字总量下限 60 字；低于 60 字说明信息量不足。
- `long` 默认形态按屏数而不是字数设限：一张长卡可承载到三个 `3:4` 屏（4320px），
  名单、多条证据这类同质内容允许继续增长到上限，不必为了 220 字先拆卡；到上限再拆卡或删减。
- 固定比例卡（`3:4`/`4:5`/`9:16`/`1:1`）仍按 60–220 字控制，超过说明该渠道放不下。

## 明确禁止

- 整段正文、源代码、Markdown 表格直接贴进卡片。
- 侧向分栏的密集网格；手机端比较项一律上下排列。
- 用生图模型生成文字、数字、图表、Logo 或伪界面。
- 为了塞进画布而缩小字号、压缩行高或删掉单位与口径。
- 用纯文字逐行罗列可比数据；三行以上可比项必须换成条形长度（`bar-ranking`）。

## 来源、附录与页脚

- 附录条目使用 `data-role="source"`（26px 下限、34 字行宽），因为完整网址比普通注释更长。

- 来源与工具写在页脚上方的 `appendix` 区块里：先用一条分割线（`.appendix-rule`）分隔，
  再用 bullets 分「数据来源」「信息图呈现」；不要写 `Appendix`、「使用工具」这类标题词。
- 单卡页脚只放品牌 Logo 并居中，不显示页码；系列卡保留左 Logo + 右 `n/N`。
- 来源行不写在本区（避免与页脚风格不一）：材料是群聊就写「数据来源：群聊记录」。
- 禁止出现本机绝对路径、数据库文件名、表名、内部工具名与账号标识（例如以 `.db` 结尾的文件名、
  数据库存放目录名、加密库名、`wxid_` 形式的账号、`Msg_` 开头的表名）；`audit` 以
  `source_hygiene`（error）拦截。
- 页脚 Logo 必需（高度 64px 起步，太小会显得像水印）；署名（`credit`）可选。交付物是 PNG，网址必须印成可读文本，
  不要写「点我」「某工具名」这类只有可点击才成立的锚文本。
- 附录每条写成「网址对应页面的实际标题，完整网址」，例如
  `数据来源：Universal WeChat Key，https://lovstudio.ai/skills/wdb-cli`；
  标题要抓页面的 `<title>`/`<h1>`，不要自造缩写。

## 条形图（bar-ranking）

- 条形长度＝数值，必须在图表容器上声明 `data-encoding`（如「长度 = 人数」「颜色 = 阵营」）。
- 必须按数值倒序排列（`audit` 的 `bar_order` 检查）；顺序本身就是编码的一部分。
- 每条条形要有精确数值与同一分母；不同分母的条目不能画在同一组条形里。
- 名单、职位、备注写在对应条形下方的 note 行，字号低于结论，不能挤进条形本体。
- 每行固定三行、整幅铺满：①条目名＋一句介绍 ②条形＋（数值） ③人员或依据；数值写在条形右端并用括号，
  不用左右分栏，避免一侧留白。
- 行数控制在 3–10；超过 10 项先合并长尾（例如「其余七城 19 人」）。

## 人名处理

- 社交平台材料优先使用**对方自己公开的昵称**（群昵称、账号昵称），不使用内部备注；公开昵称本身就是可展示身份，无需再打码。
- 只有在昵称缺失、昵称即真实姓名、或材料涉及隐私时，才按轻打码（`刘＊畅`）或整名隐去（`群友 N`）。
- 引语可以保留原文；署名同样按上述规则处理。
