# 手机可读性标准

本文件定义 1080 画布下的硬指标。`scripts/infographic_cli.py audit` 直接按这些数字判定，
修改任何一条都要同时更新脚本常量与本文档。

## 画布与比例

| 比例 | 像素 | 适用场景 |
| --- | --- | --- |
| `3:4`（默认） | 1080×1440 | 微信图文内嵌、朋友圈、小红书笔记 |
| `4:5` | 1080×1350 | 信息流占位更高的场景 |
| `9:16` | 1080×1920 | 全屏故事卡、视频封面 |
| `1:1` | 1080×1080 | 九宫格、头像位、列表缩略图 |
| `long` | 1080×自适应 | 单条论证确实需要更多高度时；不超过三屏 |

宽度恒定为 1080，导出倍数默认 2×（2160 宽），需要额外放大时用 `--scale 3`。

## 字号下限与真实视口

1080 画布在 390pt 宽的手机上显示时缩放约 0.36。换算后：

| 角色 | 画布 px | 等效显示 | 用途 |
| --- | --- | --- | --- |
| `title` | ≥ 72 | ≈ 26pt | 这张卡的唯一标题 |
| `value` | ≥ 96 | ≈ 35pt | 关键数字 |
| `claim` | ≥ 50 | ≈ 18pt | 结论句 |
| `body` | ≥ 36 | ≈ 13pt | 正文与依据 |
| `label` | ≥ 30 | ≈ 11pt | 分组标签、序号 |
| `note` / `source` | ≥ 26 | ≈ 9pt | 口径、限定、来源 |

低于 26px 的文字在手机上会明显吃力，脚本按 critical 处理。

行高经验值：中文字体栈（PingFang SC、Hiragino Sans GB）的内容区约为 1.4em。
行高低于该值时字形盒会溢出自身盒模型，`audit` 记为 `glyph_overflow` 警告；
标题实测 1.32 足够，132px 的关键数字需要 1.4。

## 行宽

按中文字符当量计数（拉丁字符按 0.55）：

| 角色 | 每行上限 |
| --- | --- |
| `title` | 14 |
| `claim` | 20 |
| `body` | 24 |
| `label` | 20 |
| `note` | 28 |
| `source` | 34 |

超过上限说明信息密度已经不适合手机阅读；正确做法是拆句或拆卡，而不是缩小字号。

## 对比度

- 正文（< 40px）：≥ 4.5:1。
- 大字（≥ 40px）：≥ 3:1。
- 品牌强调色直接用在文字上通常不达标（示例品牌橙 #EB6637 在纸色上只有 2.95:1）。
  强调色只用于线条、色块与图形；文字强调色使用 `accent_ink`。

## 安全区

- 左右边距 88px（≈ 32pt），上下边距 96px（≈ 35pt）。
- 内容不得越过安全区；排版超出画布或挤压到边缘都按 critical 处理。
- 底部页脚固定包含：品牌 Logo、署名与 `n/N` 页码。

## 一屏信息量

- 一张卡只讲一个结论，`data-claim` 有且仅有一个。
- 证据块最多 3 个，步骤最多 5 步，清单最多 5 条。
- 可见文字总量 60–220 字；低于 60 字说明信息量不足，高于 220 字应拆卡。

## 明确禁止

- 整段正文、源代码、Markdown 表格直接贴进卡片。
- 侧向分栏的密集网格；手机端比较项一律上下排列。
- 用生图模型生成文字、数字、图表、Logo 或伪界面。
- 为了塞进画布而缩小字号、压缩行高或删掉单位与口径。
