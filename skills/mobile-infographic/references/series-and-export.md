# 系列与导出

## 什么时候做系列

- 内容有三个以上并列要点，或需要“总—分—收”的叙事。
- 单卡文字超过 220 字却无法通过删减解决。
- 需要在信息流里形成可连续滑动的节奏。

系列默认三张：结论卡、展开卡、验收或收口卡。超过五张时应先重写内容结构。

## 系列一致性

同一系列必须保持一致：画布宽度、比例、左右安全区、页脚位置、标题层级与强调色用法。
差异只允许出现在模板与内容上。

每张卡通过根元素的 `data-series-index` 与 `data-series-size` 声明位置，页脚页码写成
`n/N`；`audit` 会核对二者是否一致。

## manifest.json

系列必须同时交付 `manifest.json`，字段沿用本 Skill 案例中的结构：

| 字段 | 说明 |
| --- | --- |
| `schema` | `lov-mobile-infographic/series/v1` |
| `series_id` / `title` | 系列标识与标题 |
| `ratio` / `canvas_px` / `export_scale` | 画布与导出参数 |
| `brand` | 品牌名、官网与品牌解析来源 |
| `created_at` | 生成日期 |
| `evidence` | 这套卡引用的原始材料 |
| `cards[]` | 每张卡的序号、模板、HTML、PNG、audit 文件与结论 |
| `review` | 机器审计、视觉复核与人工复核的各自状态 |

## 文件命名

默认命名 `手工川-{topic}-{YYYY-MM-DD}-v0.x-NN.png`：日期使用绝对日期，不含空格，
序号两位数并从 01 开始。文件名中的 `NN` 必须与 `data-series-index` 一致。

HTML 与 audit 保留英文短名（`card-01.html`、`card-01.audit.json`），便于脚本批量处理。

## 平台注意

- 微信图文与朋友圈：优先 `3:4`；九宫格用 `1:1`，并确认缩略图下标题仍可辨识。
- 视频号与全屏故事：`9:16`，标题重心放在上半屏，页码与署名远离底部手势区。
- 小红书：`3:4`，正文控制在 160 字以内，单位与口径留在一屏内。

## 导出检查

1. 每张卡的 `audit` 单独通过。
2. 缩略图复核：缩到 320px 宽仍能读出标题与结论。
3. 系列一致性：卡片宽度、页脚基线、页码格式完全一致。
4. 文件体积：单张 2× PNG 通常小于 1 MB；异常偏小往往意味着渲染空白。
