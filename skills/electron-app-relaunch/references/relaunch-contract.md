# 重新启动契约

## 三种不同动作

| 用户动作 | 正确目标 | 典型实现 |
| --- | --- | --- |
| 刷新当前界面 | renderer | `webContents.reload()` 或菜单 reload role |
| 重启整个应用 | main process + 新进程 | `app.relaunch()` 后 `app.quit()` |
| 应用已下载的更新 | 原生 updater | 先完成清理和 updater handoff，再退出 |

不要用前一种冒充第二种，也不要让第二种抢走第三种的安装交接。

## 开发态

开发态通常由 Node、Vite 或自定义脚本拉起，不能只调用默认的 `app.relaunch()`。重启函数应沿用实际 Node 可执行文件和开发入口参数，并在调用后通过 `app.quit()` 让父子进程关系自然收束。

## 菜单文案

用户可见菜单应清楚表达范围：

- “重新加载”用于当前界面。
- “重启 {App 名称}”用于完整应用。
- “安装并重启”仅用于已经准备好的更新。

## 验收证据

验证时至少比较旧、新实例的 PID 与启动时间；如系统可能存在同 bundle ID 的安装版和开发版，还要比较可执行文件路径和工作目录。
