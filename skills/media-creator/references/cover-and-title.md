# Cover and Title Direction

封面负责让人停下来并看出结果线索，标题负责说明发生了什么。两者不复制同一句话，也不把工具 Logo 做成唯一视觉中心。

## 封面，和可选的开场静帧

这是两个交付物，不是一件事的两种做法。先分清，本文其余内容都建立在这上面。

| | 封面 | 开场静帧（可选） |
| --- | --- | --- |
| 出现在哪 | 主页九宫格、聊天分享卡片 | 正片开头停留的那一帧 |
| 画幅 | 平台卡片比例（视频号 3:4） | **与成片一致**（竖版通常 9:16） |
| 在流程里的位置 | 与渲染并行，可后出 | Step 5 渲染的**输入** |
| 改动的代价 | 换个文件即可 | 必须重渲染整条成片 |
| 交付报告 | `creative_status` 一行 | 另记 `opening_still` / `opening_still_source` / `opening_still_fit` |

要不要开场静帧，必须在 Step 1 问清，不要默认。事后改主意等于重渲染，而这是本可以用一个
问题避免的成本。多数情况下答案是「不要」——封面已经承担了让人停下来的职责。

### 视频号封面交给 lov-channels-cover

风格锁定、标题钩子门禁、九宫格整墙检验都在那个 Skill 里，本 Skill 不重复实现，也
不绕过它的钩子门禁改常量。交接是文件级的：它输出 `cover_3x4.png`（1080×1440）、
`cover_4x3.png`（1440×1080）和 `spec.json`，本 Skill 只判定这些封面**声称的事实
与成片是否一致**——封面上的数字、平台状态、结果承诺必须在片子里真的出现过。数值
门禁查不出事实错误。

#### 两行文案的归属：第二行是系列名，不是排版变量

- **第二行（锚点条）永远是系列名**，例如「与你一起学 DeepSeek Harness」。主标题超宽、
  版面吃紧时，都不许把它换成本期概括——那是系列在信息流里唯一稳定的识别锚点。
- **主标题照抄用户原话。** 产品名撞上门禁字宽时，正确做法是报告代价让用户选（「字号会从
  192px 降到 130px」），不是缩成缩写替他改文案。

#### 门禁拦下用户指定的文案时，写本期的包装脚本

改 `score_hook.py` 的常量等于把门禁对以后每一期都静默放开，而这套门禁**只查形式不查
事实**，一旦放开就没人再挡。做法是本期目录下一个一次性脚本（EP.02 是
`output/work/ep02/cover_v05.py`）：`sys.path.insert` 进 skill 的 `scripts`，
`import score_hook` 后在运行时改 `MAX_VISUAL_WIDTH` 与 `DISPLAY_TIERS`，再
`runpy.run_path('render_cover.py', run_name='__main__')`。

新字号档要**推导**不要猜：可用列宽 `1080 − 2×76 = 928px`，得意黑每单位视觉字宽推进
`0.7825em`（8.0 单位 = 6.26em），于是 9.1 单位 = 7.12em，`928 / 7.12 = 130px`。
注意 `build_spec` 是把所有行一起定档的，放宽一行会让主标题**整体**降档。


### 画幅：封面和首帧是两个交付物，不是一张图的两种用法

视频号把这两者分给了不同场景，本来就不期待它们同比例：

| | 封面 | 视频画面 |
| --- | --- | --- |
| 服务的场景 | 主页九宫格、聊天分享卡片 | 信息流全屏播放 |
| 比例 | **3:4**（2026-08-17 实测创建页只有一个槽，标签「个人主页和分享卡片(3:4)」） | 竖版普遍 **9:16**（1080×1920） |
| 谁负责 | `lov-channels-cover` | 本 Skill |

把 3:4 封面当 9:16 首帧要裁掉左右 **25%**，标题组必然被切到。这不是工具缺一个比例档，
而是**拿错了素材**——`lov-channels-cover` 只负责封面，不该为首帧长出 9:16 档。首帧要用
就单独设计一张 9:16 图，与封面共用视觉语言，各自适配自己的安全区。

（9:16 是主流与推荐，不是平台硬性门槛：社区可见 4:3、16:9 的视频也能发布，但在竖屏容器
里会被放大裁切，属于呈现不可控，不是上传失败。封面 3:4 那一条是创建页实测，更硬。）

渲染前用只读判定算清楚，不要 `-loop 1` 直接拼：

```bash
python3 "$SKILL_DIR/scripts/check_opening_still.py" \
  --still DELIVERABLE_DIR/opening-still-1080x1920.png \
  --video WORK_DIR/body.mp4 --hold 1.5 --json
```

画幅不一致时它**默认退出码 1**，逼你显式选路，三条按代价从低到高：

1. 另做一张与成片同画幅的开场静帧，与封面共用视觉语言但各自适配安全区。
   **不要在本 Skill 里用 `scale`/`pad` 硬凑**——补边或拉伸会毁掉第一印象，而且
   渲染完才看得出来。
2. 接受 `--allow-crop`，但裁完必须抽第一帧目视确认标题组完整，并把裁掉的比例写进
   交付报告。损失超过 12% 或需放大超过 1.05x 时脚本会另外告警。
3. 放弃开场静帧，只交封面（默认，多数情况下是对的）。

`--allow-pad` 存在，但首帧带黑边是观众看到的第一画面，除非确实要这个效果，否则优先
走前两条。

### 音频要垫等长静音

`concat` 拼首帧时，音频侧必须垫一段与首帧等长的 `anullsrc`，否则整条声画前移，成果段
原声会和画面错开。`check_opening_still.py` 给出的命令已包含这一段；成片无音轨时改
`-an` 并删掉音频链。

首帧停留默认 1.5s。低于 0.6s 观众读不完标题，等于白留一帧。

### 首帧绑定这一版封面

渲染完在交付报告里写清这条前提：换封面必须重渲染。下游发布 Skill 上传的封面应与首帧
同源，否则列表页封面和点开后的第一帧不一致。

## 标题

- 优先使用真实动作和结果：跑通、发布、回读、验证、保留原声、压缩等待。
- 用户已经给出标题时，先保留原句，再做长度和平台适配；不要为了“更爆”擅自改变事实。
- 真实案例标题是《我跑通了视频号自动发布工作流》。它的力量来自具体的工作流结果，不来自夸张速度。
- 描述浏览器或工具时，让它服务于问题的解释；视频内容的主语保持在工作流、发布和实际结果。

## 封面

优先选择以下视觉线索之一：

1. 最终发布状态或回读状态的局部界面；
2. 一条清晰的流程轨迹：录屏 → 操作 → 结果；
3. 成果播放器正在播放、且能看出有声反馈的画面；
4. 前后对照：长流程被整理成可发布成片。

排版建议：

- 主文案控制在一到两行，保证手机缩略图可读；
- 使用一个强结果词和一个具体对象，例如“视频号发布”“工作流跑通”；
- 保留界面细节或时间线作为证据纹理，避免纯渐变背景配大口号；
- 颜色和字体沿用 Profile 中的品牌语气，品牌标识作为署名或辅助元素；
- 生成新图时交给图像能力，先传递封面 brief，再由本 Skill 检查封面是否与成片事实一致。

## 交付检查

- 16:9 和平台缩略图裁切后，主文案仍可读；
- 封面没有声称视频中没有出现的功能、速度或平台状态；
- 封面与标题分别提供信息，不形成重复大字；
- 输出 PNG 或可编辑 brief，并在报告中记录来源、尺寸和使用的文案。
