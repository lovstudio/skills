# Media Workflow

这个参考文件负责编辑判断。它把“能看懂、能相信、能听清、能交付”放在同一条时间线上。

## 叙事骨架

针对产品演示、自动化流程和屏幕录制，优先从真实内容中寻找以下节点：

1. **结果线索**：让观众知道这段视频最后会证明什么，不必一次解释所有背景。
2. **实际问题**：指出原流程哪里卡住、哪里重复、哪里需要人工确认。
3. **关键操作**：只保留能证明工作流成立的点击、输入、页面变化或状态转移。
4. **证据段**：放大真正改变判断的画面，例如完成状态、回读信息、生成结果或可听见的播放。
5. **收束**：让最终画面和原声停留足够长，给观众一个可验证的结论。

长录屏不按等长切片。每一刀都要回答“这段信息是否改变了观众对结果的判断”。

## 节奏规则

- 开头可以先给结果的一角，再回到问题；悬念来自信息顺序，不来自虚构冲突。
- 弹窗、上传、等待和卡顿只保留状态转折。若一个弹窗没有新信息，就删掉或压缩。
- 操作段允许加速，但按钮、输入和关键页面变化必须仍能辨认。
- 最终结果出现后减少字幕、顶栏和解释性装饰，让画面和原声完成证明。
- 任何标注“protected_audio”的片段都要在粗剪、精剪和终版回看三次确认。
- 系列长视频用独立黑幕卡划分大章：每章先显示序号与语义标题，再进入正文；黑幕不覆盖原画，
  人声在卡片期间暂停，字幕和后续时间码按卡片时长累计后移。

## 文案与主题

- 标题说清发生了什么；封面给出结果线索；视频内部只解释理解所需的信息。
- 用户给出的标题优先保留。例如真实案例使用《我跑通了视频号自动发布工作流》，主题落在“工作流跑通”与“发布结果”上。
- 尽量使用具体动词：跑通、回读、保留、压缩、验证、发布。少用空泛的效率、革命、颠覆等词。
- 工具名称可以在视频、标签或报告中出现，但叙事中心保持在实际问题、流程和证据。
- 章节标题先写一句“本章具体解释或证明了什么”的证据摘要，再压成短标题；避免用参与方式、
  制作动作或抽象气氛代替内容主题。
- 没有速度、权限、成功率或线上回读证据时，不写“秒发”“一键完成”“完全自动”等强断言。

## 信息密度检查

粗剪后逐段回答：

- 观众知道这一段在解决什么问题吗？
- 这一段提供了新的画面或声音证据吗？
- 删掉它会损失什么理解？
- 字幕是否遮住按钮、弹窗、结果状态或播放器控制？
- BGM 是否让人错过了真实反馈？

如果连续两段都只是在等待页面响应，合并为一次短暂状态信号，并在报告中记录压缩策略。

## 真实案例抽象

一次已完成的工作流成片提供了可复用的参考：约 1065.877 秒的长录屏被整理为 64.9 秒；上传弹窗从约 11 秒压缩到 2.4 秒；最终视频连续播放和原声被恢复；高潮段降低 BGM；进入成果段后隐藏解释性字幕与顶栏。最终交付为 1920×1080、30fps 的 H.264/AAC MP4，并附有响度、峰值和发布回读证据。

这些数字是该案例的证据，不是所有项目的默认时长。新项目必须从实际素材和实际回读重新测量。
