# 持续栏目的项目工作区

这个契约解决两类同时出现的问题：栏目需要按“第几期”归档，而单期制作又需要区分输入、
过程和成品。默认不要二选一，采用**顶层按期、期内按生命周期**的混合结构。

## 标准结构

```text
series-root/
├── README.md
├── episodes/
│   ├── ep01-product-a/
│   │   ├── README.md
│   │   ├── sources/
│   │   ├── work/
│   │   │   ├── project/   # EDL、脚本、字幕源、报告生成器
│   │   │   ├── cache/     # 探测、转写、抽帧等可重建缓存
│   │   │   └── renders/   # 分块、混音和中间渲染
│   │   └── deliverables/
│   └── ep02-product-b/
└── shared/                # 至少跨两期复用的栏目资产
```

已有工程不强制为了外观拆开一个仍可运行的 `work/`。先整体搬进本期，确认入口脚本与路径后，
再逐步把可复用代码、缓存和中间渲染分层；不要一次迁移同时重写全部剪辑逻辑。

## 四个边界

- `sources/`：原始录屏、补录、原声和旧版参考。输入只读，转码、抽帧和修复副本不得覆盖它。
- `work/`：本期工程状态。名字叫 work 不等于可整目录删除；系列模板、配乐合成器、EDL 和
  报告脚本都可能是下一期的输入。
- `deliverables/`：可交付成片、封面、字幕、媒体探测、音频质检和交付报告。中间片段不进来。
- `shared/`：背景、栏目级模板等确认被两期以上复用的资产。单期试验留在本期，避免 shared
  变成新的杂物堆。

每期目录名使用稳定的 `epNN-kebab-slug`。主题展示名写进本期 README 或清单，路径不要依赖
经常修改的长标题、标点或问号。

## 旧工作区迁移顺序

1. 只读盘点根目录、文件体积、媒体时长/画幅、Git 状态和脚本中的路径引用。
2. 用交付报告、字幕内容、媒体探测和脚本常量确认期数；不要只凭 `01`、`output` 等名字猜。
3. 先创建期数目录，再移动输入、整期 `work` 和正式交付物。无法确认的旧版进入
   `sources/legacy-*`，无法确认是否可重建的过程文件进入 `work/legacy-*`。
4. 整理本身不删除源素材或未知过程文件。删除缓存是后续独立决定，必须先证明可重建。
5. 把跨期复用资产提升到 `shared/`，同时保留唯一来源；不要在每期复制一份后各自漂移。
6. 更新脚本、清单、封面 spec、质检 JSON 和报告里的旧绝对/相对路径。报告优先写相对本期
   目录的路径，机器相关的安装路径不写进公开模板。
7. 重新回读每期输入和正式成片：至少检查文件存在、`ffprobe` 可读、成片可完整解码，以及
   报告声明的时长/画幅与盘上文件一致。

如果仓库已有脏改动，只移动明确归属的文件；Git 中已跟踪的成品使用可识别 rename 的搬迁，
未跟踪的大媒体不要因为整理而顺手塞进 Git 历史。是否使用 Git LFS 或外部归档由项目决定，
本 Skill 不替用户改变存储策略。

## 新一期初始化

开始新一期时先创建 `episodes/epNN-topic/{sources,work,deliverables}`，并在本期 README 记录：

- 期号、主题、输入文件和当前状态；
- 前一期要复用的工程入口与 `shared/` 资产；
- `render_status`、`audio_status`、`creative_status`、`publish_status`；
- 是否有开场静帧，以及它和封面是否为两个文件。

不要在系列根目录重新创建 `work/`、`output/` 或随手命名的素材文件夹。根目录只承担栏目索引、
共享资产和仓库配置。

## 清理门禁

清理优先级从低风险到高风险：失败渲染和重复缓存 → 可重建抽帧/转写 → 中间分块/无损母版。
原始素材、最终交付、人工校订字幕、EDL、报告生成器和系列复用脚本默认保留。只有成片通过
解码与音频质检、交付路径已经更新，并且用户明确要求释放空间时，才删除已证明可重建的过程文件。
