# 画中画：片中提到的三方内容，做完 research 再贴回去

片子里念到一个别人的产品名（`zenmux.ai`、OpenRouter、Pi Agent、Ralph、F12……），观众此刻
既没见过那个东西，也没法暂停去搜。专业博主的做法是固定的：检索名字 → 进官网 → 截 hero 区
→ 贴在画面上停几秒。这个流程可以脚本化，值得每期都走。

## 流程

1. **从字幕里定位，不靠记忆。** 遍历 cue 文本匹配名字，拿到源时间，再用和 `build_subs.py`
   同一套 `to_out()` 映射到成片时间。凭印象标时间点会错开几秒，而卡片错开就等于挡错地方。
2. **确认它到底是什么，再决定要不要贴。** 名字可能是 ASR 猜的（`Pagent` → Pi Agent、
   `还有ref` → Ralph）。先 WebSearch 核对一次：Pi Agent 是 pi.dev，四个工具 + ~300 词
   system prompt；Ralph 不是产品而是 ghuntley.com/ralph 那个循环技法。核不出来的宁可不贴。
3. **抓 hero 区**，用 `$ego-browser`（见下面的坑）。裁上部 55%~60%：hero 的标题和一句话
   说明在这里，再往下就是 feature 墙，缩到 600px 宽全糊。
4. **合成卡片**：截图 + 陶土色边框 + 底部域名条（写域名和一句话定位）+ 圆角透明。域名条是
   必要的——只贴一张网页截图，观众不知道自己在看谁。
5. **接进渲染**：`movie=卡片.png,format=rgba` 作为滤镜内输入（不占 `-i` 位），
   `overlay=x:y:enable='between(t,t0,t1)'`。**单帧 PNG 就让它是单帧**，overlay 默认的
   `eof_action=repeat` 会把那一帧按住到分块结束，这正是要的行为。**不要加
   `loop=loop=-1`「让它活着」**：无限的次输入会驱动 overlay 越过主输入的结尾，编码永不停止
   （实测一个 1501 帧的分块写到 68MB 还在涨）。**`ass` 一定放在 overlay 之后**：章节条和
   字幕是版式，争像素时必须赢。

## 位置只能量，不能挑

先测候选区的水平边缘能量（演示片屏上全是文字表格，有字就有边缘），再决定贴哪。EP.03 实测
右上 y=210..590 有 33.8% 的帧带内容，右上偏上 30.4%，右中 32.9%——**没有空区**。屏上四个
位置已经被占：顶带（章节条）、左下（系列标识）、正下（字幕）、右下（摄像头圆框）。

结论不是「找一个不挡的角」，而是承认一定会挡，所以：

- **不常驻**，只在名字被说出后停 4.5~5.0s。有英文标题要读，2.5s 只够看见有东西闪过。
- **晚于人声 0.35s 出现**：先听到名字，再看到卡片。反过来观众会以为漏了什么。
- 边框和圆角要明显，让它读起来是刻意贴上的插图，不是糊在界面上的脏东西。
- 断言底边不撞字幕带（EP.03 是 `y + h < 1060`）。

## 裁切下界：先看有什么不该进画面，再谈版式

`crop` 的上边界是为了躲开站点顶部的促销条，下边界通常收在 hero 按钮下方。但有两类东西
比版式优先，命中就必须往上收：

- **第三方 IP**。EP.03 的 Ralph 那篇（`ghuntley.com/ralph`）hero 配图是《辛普森一家》的
  角色插画，自 y≈330 起。别人的角色不进我们的画面——和封面那轮「去掉画面里的第三方商标」
  是同一条。裁到 0.36，站名 + 导航 + 标题已经足够让观众认出这是谁。
- **真人脸**。Chrome DevTools 文档页在标题下方挂作者头像（y≈355），再往下是视频缩略图
  （y≈528），也是人脸。贴陌生人的脸进片子没有必要，裁到 0.38。

两者用**饱和度**扫，不要用亮度：正文是灰的，插画和照片是彩的。每行统计
`(max(RGB) - min(RGB)) > 60` 的像素占比，超过 4% 就是彩色块的起始行。亮度扫不出来——
白底上的黑字和白底上的照片，行均值可能一样。

```python
sat = (a.max(axis=2) - a.min(axis=2))          # a 是 H*W*3 的 float 数组
colorful = (sat > 60).mean(axis=1)             # 每行彩色像素占比
first = next((y for y in range(h) if colorful[y] > 0.04), None)
```

## 抓图：ego-browser 优先，卡住就换 headless

按约定浏览器自动化统一走 `$ego-browser`。它的坑：

- **`captureScreenshot()` 返回同一个复用的临时文件名**（`ego-browser-shot-<pid>-1.png`）。
  抓完立刻 `copyFileSync` 走；并发抓会互相覆盖，而且覆盖后不报错，你会拿到另一个站点的图。
- **`help()` 的注册表和实际注入的 helper 不是一套**：它连 `click`、`snapshotText` 都答
  "Unknown helper"，但这些函数照样能调。别用 `help()` 探能力，直接调。
- **多个 `ego-browser nodejs` 进程会串行争抢同一个浏览器**，不是并行。EP.03 实测：6 个并发
  时一张截图从请求到落盘等了 52 分钟。要抓多站就用一个进程按顺序走。

**判据：进程超过 ~3 分钟没有吐出第一行 `cliLog`，且 CPU 为 0，它是卡在 task space 获取上，
不是在工作。** EP.03 连续两轮都卡在这里（27 分钟零输出、零 CPU）。此时不要重启浏览器服务
——那会抢用户正在用的电脑。改用 headless Chromium 抓，公开页面不需要登录态：

```bash
HS=~/Library/Caches/ms-playwright/chromium_headless_shell-*/chrome-headless-shell-*/chrome-headless-shell
"$HS" --headless --disable-gpu --hide-scrollbars --no-first-run \
  --user-data-dir="/tmp/hsprof_$name" --proxy-server="http://127.0.0.1:7890" \
  --window-size=1512,890 --virtual-time-budget=40000 \
  --screenshot="$out" "$url"
```

同样 4 个站点，headless 用了 8 秒。两条注意：

- **每站给独立的 `--user-data-dir`**，否则第二次启动会因 profile 被占而静默失败。
- **`--virtual-time-budget` 要给足**：hero 常有淡入动画，12s 预算下 lovbrowser 的标题还
  几乎全透明，行扫描会把它读成纯白页。40s 才稳定。抓完必须目视确认，不能只看文件非空——
  一张"渲染到一半"的截图字节数完全正常。
- 只对**公开页面**这么做。需要登录态的站点仍然只能走 ego-browser（headless 没有用户的 cookie）。

## 裁切下界写成分数，理由却是绝对行号——重抓一次就脱锚

裁切下界通常有两类理由。**版式**类（"再往下就是正文，缩到 560px 糊成一片"）跟着图的比例走，
写成分数是对的。**不该进画面**类（第三方版权插画、真人头像、视频缩略图）跟着图的像素走，
而这类理由只在**某一个图高**下与分数等价。

EP.03 两张卡踩到了：`ralph` 页的《辛普森一家》插画量在 y≈330、`devtools` 页的作者头像量在
y≈355，都量在 1512×890 的截图上，于是写了 `0.36` / `0.38`。后来这两张改用 headless 重抓成
1496×731，`0.36` 从 320px 变成 263px——这次碰巧更安全，但**碰巧不是判据**，而且脱锚是静默的：
`build_pip.py` 照跑，卡片照出，只是那条测量已经不指向任何东西了。

处置是把"这一行以下不能进画面"写成断言，和分数并存：

```python
dict(name='ralph', crop=(0.0, 0.0, 1.0, 0.36), keep_out=339),
...
if c.get('keep_out') is not None:
    cut = int(im.height * y1)
    assert cut < c['keep_out'], (
        f"{c['name']}：裁到 y={cut}，但 y={c['keep_out']} 起是不能进画面的内容")
```

行号的量法（**换过截图就要重量，不要照抄**）：按行统计饱和像素占比
`(max(RGB)-min(RGB)) > 60` 超过 6% 的第一行。亮度扫不出来——白底黑字和白底照片一样亮。
