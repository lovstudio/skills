# 帧模型（Step Model）规范

本 Skill 的统一数据契约。任何一个算法/信息流程都被翻译成：
**一份静态骨架（节点/边/伪代码）+ 一组帧（每帧记录可见状态与一句解说）**。
这与“手工川图解算法”项目里 `TraceDefinition` / `SortStep` 的建模思路一致。

## 顶层结构

```jsonc
{
  "title": "KMP 字符串匹配",            // 页面标题（必填）
  "inputLabel": "TEXT ABABCABAB / PATTERN ABAB", // 输入说明，展示在标题上方小字（可选）
  "insight": "前缀表告诉模式串失配后还能保留多少已经确认的信息。", // 关键直觉（可选）
  "layout": "sequence",               // sequence | network | matrix | bars（必填）
  "code": ["从根开始比较", "…"],        // 4–8 行人类语言伪代码（必填）
  "metricLabel": "已确认",              // 进度指标名，如“已访问/已输出/已填状态”（可选）
  "nodes": [ /* 见下 */ ],              // sequence/network/matrix 必填；bars 不需要
  "edges": [ /* 见下 */ ],              // 仅 network 常用，其余可省略
  "frames": [ /* 见下 */ ]              // 帧序列（必填，5–40 帧为宜）
}
```

## 节点与边（sequence / network / matrix）

```jsonc
{
  "id": "t3",          // 唯一 id（必填）
  "label": "B",        // 主显示文本（必填）
  "caption": "03",     // 次要小字，如序号 / 行列头 / 词尾标记（可选）
  "x": 32,             // 水平位置，0–100（百分数，必填）
  "y": 50              // 垂直位置，0–100（必填）
}
```

```jsonc
{
  "id": "t3-p3",       // 边 id（必填，需唯一）
  "from": "t3",        // 起点节点 id
  "to": "p3",          // 终点节点 id
  "label": "4",        // 边权等标签（可选）
  "directed": true     // 有向边显示箭头（可选，默认 false）
}
```

坐标是**相对舞台的百分比**（0–100）。摆放经验：

- `sequence`：所有节点沿横向排布，`y` 保持一致（如 50），`x` 按序号均分。
- `matrix`：`x` 按列均分、`y` 按行均分；用 `caption` 放行/列头。
- `network`：按结构摆放（树分三层、环状图围一圈），避免节点重叠、边交叉过多。

## 帧（frames）

```jsonc
{
  "active": ["t3", "p3"],   // 当前正在操作的元素（节点 id 或 bars 下标）
  "settled": ["t0"],        // 已确定/已完成/已访问的元素（累积）
  "values": { "t3": "B · 1" }, // 动态值：node 布局为 {节点id: 显示文本}；bars 布局为数组快照
  "activeEdges": ["A-C"],   // 网络布局：当前激活的边（可选）
  "settledEdges": ["A-B"],  // 网络布局：已确认的边（可选）
  "rejectedEdges": ["B-C"], // 网络布局：被拒绝的边，如 Kruskal 的成环边（可选）
  "note": "B 与 D 匹配，继续比较下一位。", // 一句中文解说（必填）
  "codeLine": 1             // 当前高亮的伪代码行号（0 起，必填）
}
```

### bars 布局的特殊帧

`bars` 布局没有节点，帧里 `values` 直接是**整段柱高的数组快照**：

```jsonc
{
  "values": [7, 2, 9, 4, 5],  // 当前数组（整段快照）
  "active": [0, 1],            // 正在比较的下标
  "settled": [4],              // 已就位的下标
  "note": "7 与 2 需要交换吗？",
  "codeLine": 1
}
```

> 不要把 node 布局和 bars 布局混用：bars 的 `values` 是数组，node 布局的是对象。

## 叙事写作法（note 的核心质量）

观众只看帧，所以 `note` 是讲解的主体。规则：

1. **一句一义**：一帧只说一件事。≤ 约 40 字。
2. **说具体值**：“B 与 D 匹配，继续比较下一位”，而不是“进行字符比较”。
3. **补一句为什么**：在动作之后给出原因或后果——“前缀表告诉它失配后还能保留
   前 3 位，所以模式串跳到 3，而不是退回 0”。
4. **保持学习视角**：首帧讲输入与起点，中间帧讲“刚刚发生了什么 + 这意味着
   什么”，末帧讲结论（“拓扑序列是 A → B → …”）。
5. **不堆术语**：能用自然语言说清就不用黑话；必须用术语时第一次出现给一句白话。

## 六条建模原则（反面示例对照）

| 原则 | ✅ 对 | ❌ 错 |
| --- | --- | --- |
| 最小推进单元 | 一次比较、一次交换、一次松弛 | 把整轮循环塞进一帧 |
| active 聚焦 | 每帧 1–3 个 active | active 一帧 20 个 |
| settled 累积 | 访问过的节点逐帧累积 | 每帧重画整个状态，无累积感 |
| 具体叙事 | “F(5)=F(4)+F(3)=5” | “计算下一个值” |
| 伪代码对齐 | codeLine 指向真实对应行 | codeLine 永远是 0 |
| 首末收尾 | 首帧讲输入，末帧讲结论 | 缺首帧或缺末帧 |

## 帧数控制

- 目标 5–40 帧。少于 3 帧没有演示价值；超过 60 帧演示疲惫。
- 细粒度机械操作（逐个比较小数组）合并成帧：一帧可以推进“完成一次比较并给
  出结论”。
- 递归/循环展开时，只保留“改变观众认知”的关键帧，删掉纯重复的中间态。

## 完整示例：二分查找（sequence）

```jsonc
{
  "title": "二分查找",
  "inputLabel": "SORTED 2 5 8 12 16 23 38 / TARGET 23",
  "insight": "每次比较都能排除一半元素，所以查找代价是 O(log n)。",
  "layout": "sequence",
  "code": ["取中间位置", "与目标比较", "目标更大则排除左半", "目标更小则排除右半", "命中或区间为空"],
  "metricLabel": "已比较",
  "nodes": [
    { "id": "n0", "label": "2",  "caption": "00", "x": 4,  "y": 50 },
    { "id": "n1", "label": "5",  "caption": "01", "x": 20, "y": 50 },
    { "id": "n2", "label": "8",  "caption": "02", "x": 36, "y": 50 },
    { "id": "n3", "label": "12", "caption": "03", "x": 52, "y": 50 },
    { "id": "n4", "label": "16", "caption": "04", "x": 68, "y": 50 },
    { "id": "n5", "label": "23", "caption": "05", "x": 84, "y": 50 },
    { "id": "n6", "label": "38", "caption": "06", "x": 100, "y": 50 }
  ],
  "edges": [],
  "frames": [
    { "active": ["n3"], "settled": [], "note": "目标 23。先看正中间的元素 12。", "codeLine": 0 },
    { "active": ["n3", "n5"], "settled": [], "note": "23 比 12 更大，左半边整段排除。", "codeLine": 2 },
    { "active": ["n5"], "settled": ["n4", "n5"], "note": "在剩下的 16 与 23 里取中间 16，仍然偏小，再排除 16 这一侧。", "codeLine": 2 },
    { "active": ["n5"], "settled": ["n4", "n5"], "note": "命中 23。只用了 3 次比较。", "codeLine": 4 }
  ]
}
```

> 例子里故意控制了帧数：3 次比较就是 3–4 帧，没有把每一步循环展开成十几帧。

## 生成 HTML

```bash
python3 "$SKILL_DIR/scripts/validate_viz.py" model.json
python3 "$SKILL_DIR/scripts/build_viz.py" model.json -o output/kmp.html
```

打开输出 HTML：空格播放/暂停，←/→ 逐帧，R 回到起点，右下角可调速。
