# 选样与平台

## 格式期

先翻主页，找出封面、标题版式、包装元素或栏目形态换版的时间点。默认只复刻最近一个格式期；把起止日期和判断依据写进 `sources.json` 的 `era_scope`。跨格式期混选会把两种风格平均成一种不存在的风格。

## 候选清单

把格式期内的作品写进 `research/candidates.json` 的 `items`，每条记录：

- 作品 ID、标题、发布日期、类型（视频/图文）、链接；
- 互动数（点赞、收藏、评论、分享，取平台显示值）；
- 封面版式与子类型的初判（如个案、观点口播、置顶引流、合集切片）；
- 可见时长。

只记录作品本身的公开信息，不抓评论者或粉丝的个人信息。

## 选样与留出

- **样本量。** 10–12 条为宜，至少 6 条；工具要求至少 3 条训练样本和 1 条留出样本。
- **分层抽样。** 按子类型分层，每层同时取高互动与中位互动的作品，避免只学爆款的偶然特征。
- **单独成层的类型。** 置顶、引流或服务介绍单独成层；与他人合作、转载的作品不计入。
- **留出数量。** 留出 2 条，约占 15–20%，尽量覆盖主要子类型。
- **留出时机。** 必须在下载报告之外的任何测量之前定好。选择理由写进 `selection`。
- **排序与编号。** `rank` 用主页上的顺序；`sample_id` 只用 ASCII 字母、数字、连字符或下划线，通常就是平台作品 ID。

## 平台要点

以下做法记录于 2026-11 的实际操作，平台改版后先核对再用。

### 小红书

- **需要登录态。** 未登录时，主页 `__INITIAL_STATE__.user.notes` 里的 noteId 是空串，点卡片会弹登录框。要在已登录的浏览器里读取，浏览器选择见 Profile 的 `logged_in_browser`。
- **主页列表。** 列表随滚动累积，需要去重。笔记 ID 与 xsecToken 一并记录。
- **视频直链。** 笔记详情 `note.noteDetailMap[ID].note.video.media.stream` 下有 h264/h265 等多路流；选带音轨、分辨率最高的 mp4 直链，交给 `lov-media-crawler` 的直链下载。

### 其他平台

- 抖音、快手、B 站、微博、知乎：分享链接直接交给 `lov-media-crawler`。
- 视频号：受限内容由它回退到本机微信客户端取流。

### 共同规则

不绕过付费、私密或已删除内容；不替用户登录或输入密码。登录由用户在自己的浏览器里完成。

## 下载与登记

- **核对每条下载报告。** 确认状态为 verified、文件可解码、带音轨。
- **文件名。** `lov-media-crawler` 的 `--filename` 若带 `.mp4`，会再追加一次扩展名（2026-11-08 观察到）；传不带扩展名的名字，或下载后核对。
- **登记位置。** 原片放在 `research/sources/`，`path` 写相对 `sources.json` 的路径，换机器也能复现。
- **登记顺序。** `cloner.py register` 写入哈希与参数后再 `freeze-split`。之后发现坏文件或选错样本，就开新版本重新冻结，不要改已冻结的清单。
