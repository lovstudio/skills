# Lovpen 编辑渲染交接

## TOC 只有一个真源

canonical Markdown 只维护最终 H2/H3 层级，不硬编码一份面向微信展示的目录。Lovpen 在
`--format wechat` 的 HTML 中根据这些标题生成 TOC；这样用户继续校对章节名时，目录不会
和正文分叉。

长文有多个稳定章节或子章节时，微信 HTML 的 TOC 应满足：

- 位于导语、授权说明等首屏上下文之后，第一章之前；
- 条目只来自最终 H2/H3，不额外改写标题；
- 提供克制的预计阅读时间；
- 手机宽度下字号、行高、缩进、分隔与留白清楚，但视觉权重低于正文标题；
- canonical Markdown 已有手写目录时先删除，不能同时渲染两份。

短文或章节不足以形成导航价值时允许没有 TOC，不为模板完整强行生成。

## 小字资料就地呈现

来源、背景链接和引申阅读应紧跟它所支持的段落，以小字、低对比和必要斜体呈现。它们
不是正文论点，也不是主要 CTA。

- 一项资料占一行或一个小块；
- 两项以上逐项分行或分点，保留每一项的点击目标；
- 不把多个 URL 或说明挤成一个连续段落；
- 不在文末建立无人阅读的“资料链接堆”；
- 主要体验入口、报名或下载按钮不降级成资料注。

HTML 回读时检查每个小字块的可见换行，而不只检查源码中是否有换行符。微信净化会改变
部分标签时，仍要保证读者看到的条目没有粘连。

## Caption 互斥

图内文字、`lov-image-decorator` 烧录 Caption 和图片后的 Markdown 图注只能选择一种。
图片已经自带标题或 Decorator 底栏时，删除外部重复图注；读者肉眼能看出的“原图与结果
对照”等内容不需要 Caption。Caption 想不出真实阅读任务时，结论是 `no-caption`。
