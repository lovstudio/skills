# 踩过的坑

每条：现象 → 根因 → 做法。首轮来自 2026-10-28 样片（`2026-10-28-topic-to-short`），第二轮来自 2026-11-15 样片（37 句、650 字的见闻类口播）。

## 对齐与转写

| 现象 | 根因 | 做法 |
| --- | --- | --- |
| 重读的那一句起点早了 0.45 秒，带进了念错那遍的尾巴；首句前多 0.3 秒静音 | Whisper 逐字时间（DTW）在句首句尾漂移几百毫秒 | `align.py` 在「前一段语音的末字」到「本句首字 + 0.5 s」之间找**最长静音缝**落刀，句尾同理；样片 12 句全部落在真值前 60–70 ms / 后 80–90 ms |
| 样片对齐为了逐字时间戳去调 ASR，碰上「默认云端转写、不自选本机 Whisper」的约定 | 样片的配音是自己合成的，每句起止本来就知道 | `tts.py` 同时写 `<out>.words.json`（每句按标点分短语，分句点吸附到期望点附近的停顿，见下一条）；样片一律 `align.py --words recording/tts-take.words.json`，不经 ASR。2026-11-15 样片 37 句全部 1.00，切点落在真值前 60–70 ms / 后 80–90 ms |
| 样片联系表里一行字幕几乎不出现：「这让我想起，上半年清华attrax黑客松，」被切成 1.88 s / 0.67 s，第二段只露 0.7 秒；「四个小时，十五支队伍，都是在校学生熬了两天的成果。」也切错，字幕与 b-roll `at` 偏 1–2 秒 | TTS 句中停顿长于逗号停顿，最长停顿法会切错：Seed-TTS 在英文词前后、句中强调处的停顿常比逗号处长（逗号处可能只有 30 ms），0.4.0 却取整句窗口里最长的 N−1 个停顿当分句点 | `tts.py`（0.4.1 起）按字重（中文 1、拉丁字母与数字 0.5）算每个期望分句点，只在期望点 ±max(0.3 s, 句长 12%) 内找 ≥ 60 ms 的停顿，按「停顿长 ×（1 − 距离/窗口）」取最高分；窗口内没有就落在期望点，且必须晚于上一个分句点。同一集改稿后的 41 句样片里，38 个多分句句子中同句分句语速差超过 2 倍的由 8 句降到 3 句，最差由 7.8 倍降到 2.5 倍，剩下的是句尾拖长等 TTS 自然快慢。核对：逐分句算「字数/秒」，同句内差到 3 倍以上就是切错 |
| 重转写 CER 0.122，其实成片一字未吃 | Whisper 把 `initial_prompt` 原样吐进转写（「简体中文」盖住了「提词器、封面」）；7/七、他/它算错字 | 质检转写不带提示词；先统一数字与代词；门禁用「吃字率 ≤ 3%」，CER 只作参考 |
| 吃字率 2.1%，7 处「吃字」里 6 处是脚本里的「」引号 | 转写从不输出引号，旧标点表没有「」『』，每个引号都算成丢字 | `align.py` 的标点表补上「」『』〈〉〔〕，`finish.py` 复用同一套归一化（繁转简、全角转半角、口语数字转阿拉伯数字后再比）；同一份转写重算为 1.1%，只剩 1 处 |
| 剩下那 1 处是转写里没有「坚持到底它才」，曾被归因成「一会儿 / 1会儿」写法不一 | Whisper 会漏听紧挨在相近短语后面的一段（「再坚持一会儿。坚持到底，它才…」）；数字写法两边本来就统一过 | 对照 `takes.json`：该句切点完整覆盖 TTS 真值，属转写漏听而非切口吃字。`dropped_spans` 先核切点再归因 |
| `uv run --with mlx-whisper` 报 `Using SOCKS proxy, but the 'socksio' package is not installed`；设了 `HF_HUB_OFFLINE=1` 照样报 | 环境里有 `all_proxy=socks5://…`；`mlx_whisper` 拿到仓库名就调 `snapshot_download`，huggingface_hub 离线模式下也会建 httpx 客户端 | `align.py` / `finish.py` 先把模型名解析成本地快照目录（`$HF_HUB_CACHE` 或 `~/.cache/huggingface/hub/models--<org>--<name>/snapshots/<hash>/`），已缓存就不碰网络；`--model` 也可直接传该目录。首次下载才需要 `socksio` |
| `uv run --with …` 长时间没有输出 | 经代理访问 PyPI 极慢，卡在解析和下载依赖 | 优先用已装好依赖的持久 venv（如 `~/.venvs/<name>`）作 `$PY`；只有缺包时才临时 `uv run` |
| Profile 规定的云端 ASR（听悟）脚本与配置不在了 | 外部脚本路径会搬家 | `align.py --words` 接任何 ASR 的 `[{w, s, e}]`；通道实际不可用才回退本机 Whisper，并告知专名需人工核对 |

## 声音

| 现象 | 根因 | 做法 |
| --- | --- | --- |
| 样片比真人口播快，时长偏短 | Seed-TTS 默认音色（`zh_male_jieshuoxiaoming_uranus_bigtts`）语速参数 25 实测约 7.7 字/秒，高于片型语法的上限（4.9–7.3 字/秒，中位约 6.0） | 预审时按真人约 6 字/秒估成片时长，别拿样片时长判断节奏是否超时；要贴近真人就下调 `--rate`，用 `tts.py` 输出的 `chars_per_second` 核对 |

## 画面

| 现象 | 根因 | 做法 |
| --- | --- | --- |
| 样片全脸镜头里，占位头像圈和「一句话」「不懂硬件，照样做」这类大标注叠在一起 | 占位框在 `face` 布局下垂直居中，头像落在胸口标注（`CALLOUT_Y.face = 1050`）正下方 | 起步工程 `Short.tsx` 占位分支一律顶对齐，`face` 时 `paddingTop: 560`（头像与说明落在 y 560–1000）；旧集工程 `setup_project.py --force` 更新模板 |
| 分屏上半屏的标题在手机上被状态栏盖住 | 素材面板从 y=0 开始 | `layout.ts SPLIT.brollTop = 100` |
| 全脸镜头的大标注压到字幕 | 两者纵向间距不足 | 标注放胸口（y≈1050），字幕下移到 y≈1330 |
| 横向终端截图在分屏里两侧被裁 | 一律 `cover` | `build.py` 缺省 `fit`：裁切 ≤ 25% 才铺满，否则完整显示；长截图用 `focus` 推近 |
| 终端截图英文长行从单词中间断开 | `word-break: break-all` | `overflow-wrap: break-word` |
| 提词器截图字太小、看不出「正在念的那句」 | 1080 宽视口里字号按 vw 算 | 720 宽 × 3 倍截图，并用 `--press Space` 开播后再截 |
| 封面人像发虚 | 391 px 的形象照被放大约 2.5× | 抠图记录像素尺寸，封面最多放大 1.1×；正式封面用录像里 3 秒封面表情的帧 |

## 工程

| 现象 | 根因 | 做法 |
| --- | --- | --- |
| `pnpm install` 报 `ERR_PNPM_IGNORED_BUILDS`（esbuild） | pnpm 10+ 默认不跑依赖的构建脚本 | 起步工程自带 `pnpm-workspace.yaml` 放行 esbuild |
| `setup_project.py --force` 把本集时间线重置成占位 | 整个 starter 目录覆盖 | 已存在的 `public/data/{timeline,cover}.json` 不覆盖 |
| L01 要用封面图当素材，封面又要先建工程才能渲染 | 先有鸡还是先有蛋 | `build.py --allow-missing` 先出时间线与封面规格 → `remotion still Cover34` → 正式 build |
