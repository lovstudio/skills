# 恢复手册

## 判定：thread 是否已锁死

- 扫描器输出里 `repeat_failures_same_call > 1`，或同一 session 连续出现同一 call id：
  已锁死，继续在该 thread 里做事没有意义。
- 只有一次失败且之后没有新轮次：仍按锁死处置，因为坏调用已经进入内存历史。

## 步骤

1. **停手**：不要在原 thread 重试，不要 fork；两者都会复现同一 400。
2. **确认产物**：先看磁盘上的交付物是否完整（渲染结果、审计文件、清单），多数情况下
   崩的是收尾复核，不是产物本身。
3. **尝试卸载**：把 thread 归档再取消归档，让宿主丢弃内存中的会话历史；若状态从
   systemError 变为可继续，可先发一条最小消息试探。
4. **仍失败则新开 thread**：新 thread 里只用文本读取旧 thread 的结论、文件路径与待办，
   通过宿主的 thread 读取能力获取，不要导入旧 assistant 消息或旧工具调用。
5. **把待办改成不会触发竞态的形式**：逐张看图、先缩图、或直接改用外部视觉能力。
6. **报告状态**：区分"已恢复"（新 thread 能继续）与"已止损"（产物在、旧 thread 放弃）。

## 恢复时的证据要求

- 引用旧 thread 的关键结论时给出 thread id 与时间。
- 引用产物时给出绝对路径，并回读文件确实存在。
- 不要把"新 thread 能继续"写成"问题已修复"；根因在上游竞态，本 Skill 只做止损与预防。
