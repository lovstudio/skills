# 清卡的授权、检查与结果

将“复制已完成”“备份可用”“允许删除”分开判断。权限来自当前用户上下文，不来自示例、命令参数或这个 Skill。对清卡方式的技术咨询保持只读；用户已经明确选择清卡和目标时，不再循环请求相同授权。

先完成可审阅的计划，记录：源卡路径和卷 UUID、将删除的文件、数量和逻辑字节、对应的验证报告、所有未处理或受保护文件。对尚未明确的删除授权，只提出一次聚焦问题。不要先删再解释。

## 检查顺序

1. 重新核对源 UUID、目标 UUID、挂载点与物理设备关系，排除内置系统盘和源目标重叠。
2. 确认完整 SHA-256 校验已成功，清单覆盖全部待删文件；以源文件当前路径、大小、mtime 匹配快照，并确认备份仍在且大小/mtime 未变。
3. 如果出现过备份哈希错误、备份改动、断连、来源改变或对存储健康有疑虑，重新核验，不能凭旧的完成标记清卡。当前工具会在重新校验开始时撤销 manifest 的 verified 状态。
4. 正常条件下复用已完成的核验，不为相同事实反复读取百 GB；明确记录“之前全量哈希 + 当前元数据检查”的证据范围。它不防御保留 mtime 的恶意修改。
5. 扫描保护标志。遇到 `uchg`、`schg`、EACCES 或 EPERM，记录并保留；不 `chflags`、不提权、不更改 ACL 来绕过。
6. 仅删除清单匹配项，再删除空目录。保留未知新文件；遇到中途失败，保留已删除项日志，不将部分完成报为全部完成，也不盲目重跑整卡删除。
7. 同步写入、重新枚举剩余内容、读取实际 free bytes，再报告结果。更新复制报告里的“源卡保留”状态，避免留下相互矛盾的记录。

## 如何说明备份安排

推荐多份独立备份，但不要把建议变成无条件门禁。用户明确接受单份副本、尚未恢复的 RSV 等状态后，可以在明确授权范围内清卡。不同素材分别存到本机和 SSD，不等于每份素材都有两份独立备份。

对另行转移的素材，无旧源哈希时只报告数量、原始大小和抽查结果。不得用这部分的存在证明卡上其他素材也有第二份备份。

## 清空与格式化

Sony 警告电脑直接删除电影可能使影像数据库不一致，因此通常优先在相机内格式化。用户明确要求电脑执行时，可以清理文件并保留现有 exFAT 分区；如需格式化，应另行确认具体卷/卡槽和格式，不把文件清空扩大成整盘抹除。

例如 `SONY/SONYCARD.IND` 可为 0 字节的受保护标记。保留它并报告“素材已清空，保留 0 字节标记”，不要声称文件数为零。电脑删除后是否还需要机内初始化，以相机实际表现和官方指南为准。
