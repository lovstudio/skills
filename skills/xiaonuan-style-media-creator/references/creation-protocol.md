# 晓暖风格 · 新选题创作与验收协议 v0.1

## 输入与优先级

用户提供的事实、来访者授权和安全边界优先于风格；用户指定的时长、画幅、平台优先于样本中位数。画像是带条件的规则，不是原作者本人，也不是婚恋或职业建议的知识库。

brief 使用 `assets/brief.schema.json`：`format`（call_in / solo_numbered / solo_mechanism）、`scenario_type`（factual / fictional_demo / reframed_recording）、带来源的事实、`guest.consent`、平台和 CTA。虚构演示必须标为 `fictional_demo`，不能写成真实来访。

## 内容生成

1. 先写清这条要回答的定位问题：对方是谁、要什么、市场里的可比维度是什么、他自己没说出来的约束是什么。
2. 选叙事模板：连麦个案（call_in_positioning）、个案转观点（case_to_viewpoint）、编号作答（solo_numbered_answer）或单人讲机制（solo_mechanism）。
3. 连麦个案按“求定位 → 报条件 → 追问 → 复述与改写 → 画像与取舍 → 收束 →（可选）对观众泛化”排 beat。追问 3–10 字、要数字；画像至少给三个带取值或区间的属性，并写明要接受的短板。
4. 判断落在选择和市场规则上，不对来访者做人格或心理诊断。市场类断言要么有数据来源，要么明确说是个人判断。不搬运原作对性别、职业的刻板说法。
5. 前置高光从完成的对话里挑：7–18 秒，完整句首句尾，正片原位必须再出现一次。
6. 标题最后写：个案题用“条件 + 诉求/判词/原话”，观点题用泛化结论；措辞要能在对话里找到。

## 声画时间线

- 剪辑计划用 `assets/edit-plan.schema.json`，时间以秒计、左闭右开，从 0 连续覆盖到目标时长。
- 第一段是 `cold_open`，第二段是 0.6–1.2 秒的 `separator`（彩条 + 1 kHz 提示音，提示音比人声高约 9 dB）。
- 字幕单行、每行不超过 16 个文本单位、不带标点，来自对话原文；两个声音同一样式。
- 标题两行、同字号、一行黄（或红）一行白，从 0 秒保留到正片开始之后；用资料卡时标题让位，资料卡 6–14 秒（留出样本显示也可更长，待 v0.2 确认）。
- 来访者只以头像小窗出现；平台安全区默认顶部 160 px、底部 260 px。
- 正片不加 BGM；成片默认 -16 LUFS、True Peak 不高于 -1 dBTP。

## 状态

prepared、validated、rendered_review、human_approved、published 是不同状态。没有编码好的视频文件时，只能说脚本或计划完成。自动校验通过不等于听审、盲评或用户认可。对外发布前必须确认来访者对“这一版”的同意。

## 验收顺序

1. `scripts/style_media.py validate-plan` 通过（时间线、字幕、事实、规则引用、密度、安全区、响度目标）。
2. 语义审阅：论点来源、改写是否有依据、画像是否可执行、是否出现读心或刻板判断、标题能否在对话里找到。
3. 渲染后：重新转写核对剪口，测响度与峰值，扫描黑场与长静音，抽帧检查标题、资料卡、字幕、连麦窗。
4. 封面在 3:4 缩略图尺寸下检查可读性。
