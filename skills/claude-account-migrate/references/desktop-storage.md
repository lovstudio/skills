# Claude desktop session storage

Observed on macOS with Claude desktop 2.19675.0 (2026-10-04). Anthropic does not
document this layout; re-run `scan` and re-check these facts after app updates.

## Data directory

macOS: `~/Library/Application Support/Claude/`. Override with `--data-dir` or
`CLAUDE_DESKTOP_DATA_DIR`. Third-party provider mode uses a separate
`Claude-3p` directory, so its sessions are another store again.

`config.json` holds `lastKnownAccountUuid`, the account the app is signed in to.
The tool reads it and never writes it.

## Code tab sessions

```text
claude-code-sessions/<account uuid>/<org uuid>/
  local_<id>.json          one sidebar entry: title, cwd, cliSessionId, isArchived, ...
  archived-sessions.idx    {"v":1,"archived":[...]} — rebuilt by the app from isArchived
  backlog/tasks.json       {"version":1,"items":[{"id":...}]}
  scheduled-tasks.json     {"scheduledTasks":[...]} — not migrated
```

The conversation itself is `<cliSessionId>.jsonl` under the Claude Code config
directory (`$CLAUDE_CONFIG_DIR` or the home `.claude`), in `projects/<cwd slug>/`.
That directory is shared by every account, so a copied sidebar entry resumes the
same transcript. If the transcript was deleted, the entry is a title-only orphan.

## Cowork sessions

```text
local-agent-mode-sessions/<account uuid>/<org uuid>/
  local_<id>.json          entry: title, cwd, emailAddress, accountName, cliSessionId, ...
  local_<id>/              per-session folder
    .claude/               private Claude Code config dir: projects/, .claude.json, settings.json
    audit.jsonl, outputs/, uploads/
  spaces/, cowork_settings.json, cowork_plugins/   account-level support data
  *-cache.json, debug/, rpm/                        regenerated by the app; not copied
```

- The transcript lives in `.claude/projects/<cwd slug>/`. The slug is derived from
  `cwd`, and some sessions use their own `outputs/` folder as `cwd`, which contains
  the source account UUID. Rewriting `cwd` would break transcript lookup, so the
  tool leaves it unchanged and those sessions keep writing to the source folder.
- `emailAddress` / `accountName` keep the creating account after a copy, so they
  are not reliable for identifying the account a folder now belongs to.
- The private config dir has no `settings.json` by default, so the 30-day
  transcript cleanup applies even when the user's global setting is higher.

## App behaviour after a copy

- New `local_*.json` files appeared in the session list within about 15 minutes
  without a restart; `archived-sessions.idx` was rebuilt to match `isArchived`.
- Writing while the app runs did not conflict, because each session is its own file.
- On load the app edits some copied entries: it sets `transcriptUnavailable` when the
  transcript is missing and may add `isStarred` or an empty `sessionPermissionUpdates`.
  To undo a copy, compare against the source and treat only these keys as app noise.

## Retention

Claude Code deletes transcripts older than `cleanupPeriodDays` (default 30) at
startup. Deleted transcripts cannot be recovered from the session index; only an
external backup such as Time Machine can restore them.
