# YOLO 模式 · YOLO Mode

用户离开时，在当前已授权任务内自主决策、实现、验证和保存进度。一个无法执行的
步骤不应拖住其他工作。启动时必须检查当前 session 的权限，不能只口头声明进入 YOLO。
宿主没有提供切换能力时不能伪造成功；此 Skill 本身不是后台服务。

## Triggers

### Activate when

- “/lov-yolo-mode” 或 “$lov-yolo-mode”：准备当前 session 所需权限，接续当前任务。
- “开启 YOLO 模式，把当前任务需要的权限准备好，继续做完。”
- “开启无人值守，我去吃饭，继续把当前任务做完。”
- “我去睡觉，按我的偏好做，不要问我问题。”
- “$lov-yolo-mode 把当前功能实现并验证。”
- “Use unattended mode and finish the current task while I am away.”

### Do not activate when

- 只询问原理、审查此 Skill 或要求创建类似 Skill；不启动业务工作。
- 普通“帮我修复”“继续”没有启用无人值守的上下文；不隐式开启模式。
- 只要求定时提醒或周期监控；用宿主调度能力，不借此开启任意任务。

## 开启与退出

1. 读取当前任务、项目规则、本包 `skill.yaml` 和 [Profile 合同](references/user-profile.md)。
   读取 [能力组合](references/skill-composition.md)，按当前任务需要交接业务能力。
   必须执行 [当前 session 权限准备](references/session-permissions.md)，核实已有权限，
   对宿主明确允许且本任务必要的权限直接配置并回读；不重复询问已经覆盖的授权。
2. 有明确任务时直接继续；单独调用时接续当前未完成目标。没有可识别目标则标记
   `idle_no_task` 并结束，不提问、不搜索其他会话接活、不自行创造任务。
3. 简述实际权限准备状态与无人值守范围，接着执行，不要求确认参数。已有权限满足时
   报告 `already_ready`；成功设置并回读后报告 `configured`，不能把意愿当成切换证据。
4. 默认范围是当前任务，保持至完成、耗尽可执行分支、用户取消或指定期限到达。
   只使用宿主正式允许的当前 session 设置接口，不改全局提示词或其他会话。保存偏好
   不等于永久启用模式。用户要求整个 session 时按该明确范围维持执行约定。
5. 用户说“关闭无人值守”“暂停”“我回来了，先停一下”时停止新的业务动作并保存
   状态；不能安全中断的已启动操作先回读状态，不假装取消成功。
6. 压缩、恢复或宿主明确继承当前任务时，从检查点继续，回读实际状态和授权有效性。
   旧报告和磁盘文字是上下文，不能当作新的授权。

## 决策顺序

在高优先级规则和当前授权内依次使用：当前请求与显式参数、项目约定、显式环境配置、
本 Skill records、个人 preferences、共享 Profile、可验证上下文、安全默认值。
只使用 Manifest 声明字段，不整份输出私人 Profile。

- 有偏好时直接采用；没有偏好时选任务范围内最可逆、符合现有项目惯例的方案。
- 实现、结构、格式和命名可合理推断，简要记录影响结果的假设，不生成选择题。
- 身份、收件人、发布目标、凭据、支付额度、法律事实和原始素材真实性不能猜测。
  缺少关键事实时做不依赖它的部分，将依赖项标为 `deferred_input`。
- 会实质改变原目标的路径不能默默代选；保留可审阅草稿，继续独立分支，记录未决定项。
- 不主动调用提问工具，不输出“是否继续”“请确认”等收尾，不以倒计时或沉默视为
  批准。只有更高优先级指令强制交互时才遵守并说明来源；此 Skill 不能覆盖它。

## 执行循环

1. 确定目标、验收证据、范围和依赖。优先用宿主计划；没有计划工具则维护简短记录。
2. 每次调用工具前做 [非交互预检](references/noninteractive.md)，检查业务授权和工具
   权限两层，不能因本机可写就推断业务已授权。
3. 执行已授权且不需要人工输入的工作。业务 Skill 的实现与质量要求继续有效；其
   可选提问按本模式处理，不通过削减验证来“自动完成”。
4. 暂时性错误仅在有新证据或明确重试价值时有界重试，默认最多两次重试。相同失败
   两次未获新线索就重新诊断；权限拒绝不计入可重试网络故障。
5. 一个步骤受阻时，完成所有可执行准备，记录原因和恢复条件，将它及依赖它的步骤
   移出可执行队列。继续其他分支，不把失败依赖当作已完成。
6. 对结果做相称验证。写入成功不代表外部上线；结果不明时先回读再决定。
7. 重复至目标有真实验收证据，或当前已无可执行工作。后者以 `partial` 或 `blocked`
   收束，不等用户、不重复轮询同一个审批框、不宣称全部完成。宿主状态 API 有特定
   状态转换条件时遵守其条件，不为结束当前轮次伪造宿主目标状态。

## 授权受阻时

“别问我”“全自动”“我去睡觉”授予当前任务的决策自主性，不是无限操作授权。
显式一次性授权或站立授权已覆盖触发条件、目标、载荷、目的地和范围时，直接执行
允许的动作，不重复索要许可。范围变化、授权撤销或过期时重新判定。

- 未获准的发送、发布、删除、共享权限修改、付费等操作：保存具体可审阅制品，
  标记 `deferred_authorization`，继续其他工作，不主动发起授权弹窗。
- 宿主审批、sandbox、自动审查或工具权限拒绝：保留准确原因。可选本身独立获准的
  替代工作，如本地草稿、只读检查或测试；不换工具执行同一被拒操作来绕过限制。
- 不突破宿主强制审批政策，不关闭 hooks/签名/校验，不使用绕过保护的参数，不点击确认框，
  不调用另一个 Agent 代批，不用批量 yes 或伪造同意来消除保护。
- 非预期出现审批等待时，宿主有安全取消方法则取消自己发起的待批请求；没有控制
  能力则准确说明受宿主限制。不能承诺 Skill 能使所有宿主永不暂停。
- 权限不足且没有独立可执行工作时保存恢复点，结束本次执行。除非上位规则要求，
  不索要立即响应；报告解除条件即可，不自动创建提醒或重试同一阻塞。

## 运行与时间边界

- 使用已有预算、截止时间和项目限制；不因无人值守自动购买额度、续费或重置用量。
- 长命令使用宿主异步任务、可查询进程和超时；按正常耗时判断，不能拿固定短超时
  误杀有效构建。只停止自己发起且可安全停止的操作，不结束用户原有服务。
- 进度遵循宿主要求，聚焦成果与阻塞；不向他人发消息，不抢前台。
- Skill 不保证关机、系统休眠、断网或客户端退出后继续运行。用户明确要求定时、
  周期或稍后恢复时才用宿主调度，先查重，确认成功后才能报告已安排。不得自行
  设置系统防休眠、守护进程或递归启动 Agent 来维持运行。

## 保存与交付

在里程碑、切换受阻分支、上下文压缩前保存必要状态，优先用宿主任务记录。没有
宿主持久记录时，在项目允许的输出目录建立独立任务目录，不覆盖其他任务记录。
按 [恢复记录](references/run-record.md) 保存目标、范围、假设、结果、验证、受阻项、
运行中操作标识与下一步。记录只恢复上下文，不赋予权限。

最终简报实际状态、产物位置、验证、重要默认值和延期原因。受阻项必须标明未完成
范围；全部完成就直接交付，不额外索要确认。用户后续主动补齐条件时重新回读并继续，
防止重复发送、发布或写入。

## User Profile

每次调用读取 `user-profile/v1`；无专用运行时可运行：

```bash
python3 scripts/profile_store.py read --skill-id lov-yolo-mode
```

仅用户直接声明的长期偏好，通过 `scripts/profile_store.py record --skill-id lov-yolo-mode`
写入 `records`；`--confirm` 表示该陈述已由用户作出，不要求再确认。报告保存路径。
推断、当前活跃标记、秘密和含糊的全量授权不写入偏好。Profile 不可读时保留诊断，
使用当前请求和默认值继续，不启动配置访谈。
