# 当前 session 权限准备

调用 /lov-yolo-mode 时必须执行本阶段。用户明确要求当前 session 进入自主执行模式，
并启用当前任务必要的权限；不要再次询问是否准备权限，也不能仅修改文案就宣称准备完成。

## 必须按顺序执行

1. 确认当前宿主、当前 session、原任务范围及宿主实时声明的权限。优先采用宿主提供
   的 session 上下文或正式状态工具，不用某份全局配置推断已运行 session 的实际状态。
2. 根据真实任务列出必要能力，例如项目文件读写、命令执行、网络或指定应用连接。
   “所有必要权限”指这份需求集合；未使用的连接器、账户、系统隐私权限不在集合中。
3. 已经具备的权限直接使用，不重复设置。宿主有正式允许的 session 权限接口时，
   在用户明确授权和高优先级规则允许的范围内配置本任务所需权限，然后回读实际状态。
   只能使用当前真实提供、语义和作用域已核实的接口，不能编造命令或工具参数。
4. 模式切换请求不覆盖宿主强制规则。接口不支持热切换、切换要求人工操作或更高层
   策略拒绝时，记录具体缺口并继续已获准的独立工作，不等待用户、不反复触发授权。
5. 如果所有能力已就绪，直接进入任务执行与验证。不能为“强制切换”而重新启动
   session、复制身份、修改内部状态数据库、编辑宿主注入的权限声明或启动免审批子进程。

## 状态与证据

- `already_ready`：当前宿主实时声明已满足该任务所需能力，无需切换。
- `configured`：正式接口完成配置，已回读当前 session 生效状态。
- `partial`：部分必要能力缺失，仍能推进独立分支；报告缺口及受影响任务。
- `unsupported`：需要的 session 设置没有真实可调用接口；不能声称全权限已开启。
- `blocked`：所剩任务全部依赖缺失能力；保存恢复点并结束本轮。

记录能力、是否必要、当前状态、证据来源、改变动作与回读结果。不要记录凭据。
配置写入成功、工具安装成功或应用连接存在，不分别等于 session 生效、全部获权或业务授权。

## 宿主能力的区别

对于明确声明 `sandbox_mode=danger-full-access`、`approval_policy=never` 且网络开启的
session，文件与命令所需权限可判定 already_ready；仍按实际任务检查第三方连接。
这是条件判断，不能假设所有运行环境都这样设置。`never` 不会替其他受限环境自动放权。

应用工具的 read/write/confirm 设置与 session 权限是不同层次。只有本任务明确需要该
应用、用户授权覆盖该范围且工具支持时才配置；不把应用授权工具用作 session 切换器。
不自动授权所有安装的插件，不虚构 OAuth scope，不修改操作系统隐私数据库或安全策略。

若更高优先级指令强制询问或审批，遵守并说明来源。当前 Skill 无法承诺取消这种限制。
用户撤销模式时停止新的任务动作；如本次曾临时变更 session 设置且宿主支持恢复，则按
保存的原状态恢复自己的变更，保留原本就存在的权限，不影响用户其他任务。
