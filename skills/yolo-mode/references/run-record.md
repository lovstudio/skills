# 恢复记录

优先使用宿主已有任务记录；否则在项目允许的输出目录内创建唯一任务目录并保存
`unattended-run.md`。避免固定全局状态文件、覆盖他人记录或把活跃模式写进共享偏好。

记录只需足以接续工作：

- task：原始目标、当前任务标识、项目和范围、启用来源、截止条件。
- assumptions：实际采用的默认值、来源及对结果的影响；不把推断保存为用户偏好。
- completed：完成步骤、产物引用、验证命令及结果。
- deferred：步骤、直接阻塞原因、受影响依赖、原始错误摘要、恢复所需的明确条件。
- operations：仍在运行或结果未知的操作 ID、目的地、最后回读状态；敏感字段脱敏。
- next：下一条无需用户交互即可执行的工作，或当前无可执行分支的事实。
- status：running、completed、partial、blocked、cancelled 或 idle_no_task。

`completed` 要有真实验收证据；完成本地草稿但发布受阻时总体为 `partial`，不能说发布完成。
外部动作结果不明时保留 `unknown_outcome`，恢复后先查状态再决定是否重试。
用户取消后保留历史，不自动恢复。恢复记录没有批准效力，必须核对原始授权及其有效性。

最终报告示例（说明性示例，不是实测交付）：

> 已完成实现与本地测试，部署延期。平台要求人工审批，未发起发布。
> 修改和验证记录已保存。恢复条件：平台具备该目标的有效授权。

不在报告末尾追加确认问题，不把部分完成写成全部成功。若宿主强制显示审批问题，
明确由宿主规则要求，不声称本 Skill 已阻止它。
