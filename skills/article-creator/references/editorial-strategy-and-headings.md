# 创作战略与标题系统

## 1. 先定义要发生的变化

每篇文章先建立一份不直接展示给读者的 `strategy brief`：

- `conditions`：作者现有的事实、素材、身份、关系、渠道、时间与风险边界；
- `motivation`：为什么是作者、为什么是此刻、为什么值得写；
- `objective`：文章希望获得的传播与业务结果；
- `reader_start`：目标读者读前知道什么、相信什么、缺什么；
- `desired_reader_change`：读完后希望读者怎样理解、感受、判断或行动；
- `evidence`：哪些真实现场、对话、图片、结果和外部资料能够推动这项变化；
- `gaps`：还缺什么，缺失是否足以阻止可靠成稿。

用户输入是真实任务的一部分，但其中的结构提议、解释和传播判断可能不充分。Agent 的
责任是像编辑与谋士一样，结合条件和目标发现缺口；不能以“尊重输入”为由复述一个
无法实现目标的方案，也不能在没有说明的情况下替用户改掉已经明确的决定。

## 2. 按交互上下文选择推理方向

| 输入状态 | 默认方法 | 必须保护 |
| --- | --- | --- |
| 只有命题或项目 | 自顶向下：目标 → 读者变化 → 证据 → 结构 | 已知事实与发布边界 |
| 已给开头或章节 | 约束式补全：固定已给部分，再补缺口 | 用户明确接受的文字与层级 |
| 语音转写或思绪草稿 | 自下而上：事实簇 → 动机 → 命题 → 结构 | 真实语气、关系与不确定性 |
| 已有完整稿件 | 迭代式：最小改动修正高影响问题 | 已校对段落、标题和素材位置 |
| 混合输入 | 分层处理：已决定处固定，未决定处推演 | 决策边界本身 |

只有一个缺口会实质改变文章命题、公开风险或最终行动时，才向用户提出一个聚焦问题。
其他缺口优先通过材料检索、保留边界或可逆草稿解决。

## 3. 标题不是同一个字段

- **文件名**：服务本地检索、版本与归档，可包含日期和版本号，不承担传播任务。
- **平台标题**：服务打开率与准确预期，只承诺正文能够兑现的一件事。
- **正文 H1**：canonical 标题真源；发布平台可把它移入标题字段并在正文隐藏。
- **H2**：划分主要认知阶段，让读者自然产生“继续读下一步”的动力。
- **H3**：在一个阶段内区分正交问题、机制或判断。
- **TOC 标签**：默认镜像最终 H2/H3，用于导航；不另造一套标题，也不反向主导结构。

章节标题不负责压缩本节所有信息。好的章节序列先让读者经历一条清楚的认知路径，
再由正文完成论证。标题可以朴素，但不能只是“背景介绍”“案例分析”“总结”这类无
区分度容器。

## 4. 章节命名门禁

1. 先说清章节之间按什么轴区分，再命名；同级标题必须尽量正交。
2. 用问题的本质命名，不用人物性别、素材编号或偶然出场顺序代替本质。
3. 没有真实时序或依赖时，不使用“先……再……”“第一步……第二步……”制造流程。
4. 不把正文结论整句搬进标题，也不把每个标题都写成悬念或金句。
5. 用户已经明确给定标题时，默认视为结构约束；若必须调整，先说明它怎样阻碍文章
   目标，再提出范围最小的替代。
6. 只看 H2 序列时，读者应能感到认知在推进；只看单个 H2 时，不要求它概括本节全部
   事实。

## 5. 证据与真人感

真实人物关系、现场对话、群聊回复、失败细节和阶段结果可以显著增强传播，但必须同时
满足：来源可回读、公开表述准确、人物或素材已获授权、与当前公开场景一致。获得授权
只解决权利问题，不代表不同场合的素材适合被拼成同一组证据。

正文提到一个对理解至关重要的现场或变化过程，且已有对应图片、聊天截图或结果时，
优先在相邻位置展示证据。图片承担了事实后，Caption 和正文不要再机械复述肉眼可见内容。
