# 八个维度

规则草稿必须覆盖下面八个维度，每个维度一句摘要、至少一条规则。阅读时按维度记笔记，带段号。

| ID | 名称 | 读什么 | 常用度量 |
| --- | --- | --- | --- |
| `voice` | 叙事视角与人设 | 人称、自称、与读者的距离；判断挂在什么经验上；是否主动披露偏好与利益；是否把读者当老读者 | `pron_wo_per1k`、`pron_ni_per1k`、`pron_dajia_per1k` |
| `structure` | 篇章结构 | 开头第一二段做什么；何时交代写作理由；分节方式；案例排列；结尾怎么收 | `first_para_units`、`last_para_units`、`headings_per1k` |
| `argument` | 论证方式 | 判断先行还是铺垫后揭示；证据类型（亲测、数字、对比、引用）；类比与跨界概念；反方与缺点；失败叙事 | `digit_per1k`、`markers_per1k` |
| `rhythm` | 句式与节奏 | 一句成段、句长分布、落锤短段、预告—揭示、逗号停顿、感叹与问句 | `one_sentence_para_ratio`、`sent_units_*`、`short_para_ratio`、`punct_*` |
| `lexicon` | 词汇与口头禅 | 坦白标记、程度副词、叠词、圈内口语与粗口、英文术语夹用、团队主语 | `signature_ngrams`、`latin_per1k` |
| `rhetoric` | 修辞与情绪 | 复沓与排比、格言收束、自嘲与吐槽、情绪的表达方式、语气符号 | `punct_dots_per1k`、`punct_exclaim_per1k` |
| `layout` | 版式与平台元素 | 配图密度与引导句、链接与代码块、小标题形态、加粗、列表 | `images_per1k`、`bold_per1k`、`list_block_ratio` |
| `packaging` | 标题、选题与品牌位 | 标题句式与标点；选题范围；文末固定段（CTA、署名、联系方式）；口号与祝愿 | `title_*`、`boilerplate` |

## 阅读要点

- **区分风格与身份。** “我们公司”“我做了十年设计”“我的某某产品”是身份事实；“用团队真实用法做证据”才是风格。规则写后者，身份写进 `brand.identity_tokens` 与 guardrails。
- **区分风格与观点。** 作者对某个模型、公司的褒贬是观点，不迁移；“先亮判断再给亲测”是风格，迁移。
- **区分风格与笔误。** 错别字、重复字不是风格。
- **品牌位只迁移形态。** 记录“文末三段：CTA、署名、联系方式”这一位置与功能，内容由使用者自己的 Profile 填。
- **例外要写。** 规则在某类文章里不成立（发布会汇总没有亲历、教程不用跨界类比），写进 `exceptions` 或缩小 `scope`。

## 度量的口径

- 单位：中文字符 + 英文/数字词（`units`）；`per1k` 为每千单位。
- 段：导出 Markdown 的一行；纯图片行记为图片，不计段。
- 固定段落（在 20% 以上训练文章的开头或结尾重复出现的段）不计入正文度量，单列在 `boilerplate`。
- 分布：每篇一个值，报告 n、P10、P25、中位、P75、P90；布尔量报告占比。
- 带内吻合：草稿落在训练 P10–P90 的指标占比。作者本人的留出文章通常也只有约七成在带内，这是预期，不是缺陷。
