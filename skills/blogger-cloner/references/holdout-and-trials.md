# 盲测与留出检验

留出检验回答两个问题：规则在没读过的文章上还成立吗？按规则写出来的东西，表层上落在作者的范围里吗？两件事都要在打开留出原文之前做好准备。

## 顺序

1. `freeze`：风格包冻结。
2. `holdout-brief`：只发标题、摘要、日期和目标篇幅，正文仍封存。
3. 写试稿，`stylometry.py audit` 自查，`trial-register` 登记。登记时留出仍封存的试稿记为 `blind: true`。
4. `holdout-open`：解封，计算留出度量，生成 “规则 × 留出样本” 报告模板。
5. 逐篇通读留出原文，写 `research/holdout-annotations.json`，`holdout-fill` 合并。
6. `holdout-check --write-summary`：校验并汇总。
7. 可选 `blind`：生成真假配对给人工盲评。

## 盲测试稿

- **画像稿（`--label pack`）**：按风格包写同题文章。不编造具体测试、数字和个人经历；需要亲历的地方写成判断或设想，并接受“我”的密度因此偏低。截图位用 `![截图：说明]()` 标出。文末品牌位用中性 CTA，不用原作者的签名语。
- **对照稿（`--label control`）**：不参考风格包，按宿主模型的默认公众号写法写同题文章，作为基线。对照稿要认真写，不故意写差。
- 审计 `fail`（20 字以上原文重合、身份标识）必须改；`warn` 只修真实偏离。审计可以在登记前反复跑，它只用训练集数据。
- 每篇登记一次，登记后不能替换。

## 标注格式

```json
{
  "items": {
    "rhythm.setup_reveal": {
      "HOLDOUT_ID": ["hit", [["原话片段", 37]], "备注"],
      "HOLDOUT_ID_2": ["miss", [], "为什么没出现"]
    },
    "packaging.title_sentence_period": {
      "HOLDOUT_ID": ["hit", [["TITLE", 0]], "以句号结尾"]
    }
  },
  "suggested_revisions": ["下一版要改的规则与理由"]
}
```

- 结果取 `hit`、`partial`、`miss`、`not_applicable`；每个“规则 × 留出样本”都要有结果。
- `hit`、`partial` 至少一条引文（从留出原文中定位）；标题规则用 `"TITLE"`。
- `miss`、`not_applicable` 必须写备注。
- 度量类规则按留出原文的度量值判定，并在备注写出数值与训练带。
- 解封前已经在日志里见过的留出内容，在条目上加 `"contaminated": true`。

## 汇总怎么读

`holdout-check` 写入 `summary`：

- 覆盖率、各结果计数、独立命中（未受污染、风格包在解封前构建）；
- 每篇留出原文的度量带吻合与带外指标——这是作者本人的基准线；
- 每篇试稿的审计：状态、带内比例、原文重合最长片段、身份命中；
- 三组带内比例均值：留出原文、画像稿、对照稿。

画像稿接近留出原文、且明显高于对照稿，说明表层特征迁移成功；它不证明质量和可读性。质量结论只来自人工盲评或真实读者反馈。

## 人工盲评

`blind` 把每篇画像稿和对应留出原文去掉图片后随机排成 A/B，答案存在 `.key.json`。请读者逐对选出哪篇是原文，用 `blind-score --answers 1=A,2=B --reader 名字` 记分。Agent 不替读者作答，也不打开答案后再“评”。

## 修订

修订意见只写进 `suggested_revisions`。要改规则就开新版本：复制草稿、修改、`build` 到 `SLUG-v0.2`。新版本在解封后构建，留出结果自动标记为受污染；需要独立检验时另留新的留出样本（新工作区）。
