# Authorship Integrity Contract

本 Skill 的正常产出是关于另一位作者的分析（风格画像、说明书）和按画像写的试稿，`metadata.content_class` 为 `authored-prose`。下面的约束适用于规则草稿、说明书、盲测试稿，以及由它封装的专属写作 Skill。

## 分析时的账本

写规则和说明书之前，先分清四类东西：

- `style`：可迁移的写法——结构、节奏、论证路径、修辞、版式、品牌位的形态；
- `identity`：作者的身份事实——名字、账号、产品、公司与业务、职业经历、粉丝量、联系方式；
- `opinion`：作者对人物、产品、公司、行业的判断与商业立场；
- `noise`：错别字、重复字、排版事故。

只有 `style` 进入规则；`identity` 进入 `brand.identity_tokens` 与 guardrails；`opinion` 只能作为“原作者这样论证”的证据，不作为事实写进说明书；`noise` 不迁移。

## 写作时的账本（试稿与专属 Skill）

- `source_question`：这篇要回答的真实问题；
- `author_positions`：使用者明确给出或确认的判断；
- `firsthand_evidence`：可以写成第一人称的亲历、测试与数字；
- `forbidden_inventions`：使用者没有提供的经历、测试、数字、引语和因果；
- `open_questions`：应保留到成稿里的不确定性。

盲测试稿没有使用者材料，只能写判断与设想；把“我目前的判断”“从公开信息看”写明，不写成“我测过”。

## 篇章审计

润色句子之前检查：

1. 论点溯源：每个主要判断都能追到证据或使用者的决定；
2. 因果压缩：不把复杂过程写成一条整齐的因果；
3. 反证保留：有意义的例外和反方不被删掉；
4. 收束压力：结论不超过证据允许的范围；
5. 读者推断：留给读者自己连接的空间；
6. 结构不对称：章节大小由材料决定，不为配平补段落；
7. 作者决定痕迹：写清为什么选这个事实、这个例子、这条边界。

## 边界

- 不复制原文句子；与语料连续重合 20 字以上视为复制，审计失败。
- 不冒充原作者，不使用其名字、账号、产品、签名语与联系方式。
- 不为了“像”而编造口头禅以外的个人噪声、错误、回忆或情绪反转。
- 度量带吻合不是作者性或质量的证明。
