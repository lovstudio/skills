# 连续视频增强

默认方向 bright-documentary 来自真实用户认可的明亮课程照片。迁移的是主体清楚、肤色自然、暗部可见与投影可读的目标，不是把 AI 修图纹理复制到视频帧。

确认 SDR BT.709、HDR 或 Log。不能凭相机型号猜测 S-Log；未标记色彩先看元数据和代表片段。当前 CLI 是 SDR 管线，其他传递函数必须先做明确颜色变换。

至少查看开头、中间、结尾及照明/人物/课件变化后的窗口。保留黑位，用单调曲线提亮中间调；白平衡克制，不能把偏蓝变成橙色。检查边框发灰、皮肤发白、白衣过曝、紫色页面失真和文字不可读。

grade 支持 mode=neutral 或 bright-documentary、单调 curve 点列、受限 balance 通道。所有参数结构化且有界，不接受任意 shell 或过滤字符串。段内参数稳定，明确场景变化后才重新校准。

实录测试默认曲线锚点为 `0/0 .05/.02 .1/.15 .2/.4 .3/.58 .5/.75 .7/.86 .9/.95 1/1`，配合轻微去蓝。它经过白底、暗底和紫色课件的短窗检查，是当前素材起点，不宣称适配所有摄影条件；明亮原片使用 neutral 或重新校准。

视频额外验收曝光泵动、时序噪点、拖影和突变；不得修改五官、动作、人数、课件或补造细节。低质量但有内容的段尽量保留；不可恢复的细节如实标记。

保持原速、原音高和原声，不擅自降噪到吞字。按源分辨率导出。硬件编码与 CPU 编码都需回看课件和人物，先短窗 benchmark；报告实际速度和大小，理论估算不是完成证据。

优先按定稿计划一次增强并编码。若用户同时要完整增强版和精简版，允许先做主片，再以更高码率重编码裁切；每次编码与父主片哈希要可回溯。测试中普通 stream copy 出现尾部多 2 帧，原生 passthrough 拼接也出现平均帧率变化，因此不能仅凭“无需再次压制”跳过剪口验收。

实现依据：[FFmpeg filters](https://ffmpeg.org/ffmpeg-filters.html) 的 curves、colorbalance 及音视频分析接口；先检查本地可用过滤器和编码器。
