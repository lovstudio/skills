# Skill Group Composition

## Nearby Skills Inspected

- `lov-riso-portrait`：把单人照片用 gpt-image-2 重绘成身份保真的 Riso 头像。输入、
  身份约束和三尺度验收与本 Skill 同构，但输出是有限色墨的插画媒介，不是黑白照片。
  属于并列的兄弟能力，不重叠，也不组合。
- `lov-professional-portrait`：保留彩色照片媒介，负责职业照精修、提亮、去帽补发型和
  背景整理。它不重新打光成黑白棚拍，也不处理表情和景别重构，因此不是重叠实现。
- `lov-image-creator`：通用生图、代码渲染与提示词工程。它可以生成图片，但不拥有
  身份保真的黑白头像验收，也不绑定本 Skill 使用的模型与通道。
- `lov-nano-banana-pro`：把图像需求整理成结构化提示词，只交付提示词文本，不生成也
  不验收人像。
- `lov-image-decorator`：给现有图片加底部说明栏与品牌 Logo，可以消费本 Skill 的成品。
- `lov-visual-clone`：从参考设计图提炼视觉要素并生成复刻指令，对象是版式设计而不是
  单人照片的身份保真重绘。

## Atomic Handoffs

- 上游输入由用户提供：一张获得授权的单人照片。本 Skill 从查看原图、规整参考图开始
  负责。
- 核心原子是 `lov-bw-portrait`：输入原图与最小简报，输出通过身份、黑白棚拍质感、
  事实细节和头像尺寸验收的方图，以及与原图出入的如实说明。
- `lov-professional-portrait` 可以在用户明确要求时先修复曝光或去掉遮挡，但它的输出
  必须重新作为本 Skill 唯一的身份参考，不能在两项能力之间混用身份来源。
- 下游 `lov-image-decorator`、名片与海报设计、文章排版或头像上传能力可以消费最终
  图片文件；它们不能替代本 Skill 的身份与事实检查。
- 更换社交账号头像、归档到品牌目录、发布到任何渠道都在本 Skill 之外，需要用户另行
  要求。

## Overlap Decisions

没有发现拥有同一结果契约的 Skill。`lov-riso-portrait` 的流程骨架被有意沿用，以保持
人像类能力的一致体验；两者各自维护自己的风格说明、提示词和案例，不共享文件。相比
兄弟能力，本 Skill 多带一个确定性 CLI，因为参考图规整、余额预检、单点修正和前后
对比在真实使用中反复出现，值得固化。

## Composition Decision

本源是 Single Skill。参考图规整、提示词组装、生成、三尺度验收和单点修正共同服务
一个头像结果，拆成 Kit 会让身份约束在模块之间丢失。相邻能力都通过图片文件可选交接，
不作为依赖安装。
