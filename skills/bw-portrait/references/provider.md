# 生图通道

## 默认通道：自带 CLI 加 OpenRouter

`scripts/bw_portrait.py` 通过 OpenRouter 调用 GPT Image 2。

| 项目 | 值 |
| --- | --- |
| 密钥 | 环境变量 `OPENROUTER_API_KEY`，脚本不打印、不落盘 |
| 模型 | `openai/gpt-5.4-image-2`，可用 `--model` 或环境变量 `BW_PORTRAIT_MODEL` 覆盖 |
| 接口 | `POST /chat/completions`，带 `modalities: ["image", "text"]` 与 `image_config.aspect_ratio: "1:1"` |
| 地址 | 默认 `https://openrouter.ai/api/v1`，可用 `OPENROUTER_BASE_URL` 覆盖 |
| 输出 | 1024×1024 PNG，同目录保存本次使用的提示词 |

模型 ID 会随服务商更新。调用报 404 或模型不存在时，先向服务商的模型列表核对当前的
GPT Image 2 标识，再用 `--model` 指定，不要凭记忆猜。

## 费用、耗时与余额

以下是 2026 年 11 月真实运行的观测值，会随服务商调整：

- 每张 1024×1024 约 0.24 到 0.27 美元。
- 每张约 110 到 160 秒；多张并行时总耗时接近单张。
- 账户余额低于 1 美元时，生图请求直接返回 402：
  `This request requires at least $1.00 in balance for image or video output`。
  这是余额下限，调低 `max_tokens` 重试没有用，只能充值。充值是使用者自己的操作。

所以开工前先运行 `balance --images N`。它只读查询账户余额，按每张 0.30 美元估算
本轮所需，不足时以退出码 3 结束。余额不够就在开工前告诉用户。

同一个账户可能同时被别的任务使用，两次查询之间的差额不一定都来自本 Skill。报告费用
时以脚本日志里每张的 `cost` 为准，余额变化只作参考。

## 运行约定

- 生成超过两分钟或同时生成多张时放到后台运行，完成后再回来验收，等待期间不轮询。
- 网络断连、超时和 5xx 自动重试，最多三次。400、401、402、403、404 不重试，
  原样报告状态码与服务商返回的错误信息。
- 日志里出现 `saved` 才算生成成功；`GAVE UP` 表示这一张失败，其余并行任务不受影响。
- 脚本拒绝覆盖已有文件。需要重跑同名输出时换一个 `--name`，确认要覆盖才加 `--force`。
- 生成后不自动打开图片，不抢占前台窗口。

## 上传与隐私

- 参考照片会以内联数据的形式发给 OpenRouter 和上游模型服务商。开工前按 SKILL.md
  Step 1 向用户说明或确认。
- 请求里只带图片和提示词。不要把人物姓名、联系方式、账号等信息写进提示词。
- 提示词文件会保存在输出目录，交付或分享前检查里面没有不该外传的描述。

## 替代通道：宿主自带的图像编辑

宿主提供 gpt-image-2 图像编辑工具时可以直接用它，条件是：

- 能把原图作为编辑目标传入，并输出 1:1 方图；
- 使用 `generate --dry-run` 或 `fix --dry-run` 打印出的提示词，保持同一套身份约束；
- 验收门、单点修正和如实说明的要求不变。

`prepare`、`compare`、`thumb`、`export` 不依赖生图通道，两种通道下都照常使用。

没有任何可用的 gpt-image-2 通道时停止，并说明缺少的是密钥、余额还是模型权限。
