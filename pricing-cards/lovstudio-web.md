# lovstudio-web · Pricing Card

把本机 Agent 接到 lovstudio.ai：读取真实目录、文章与文档，同步账号已购状态，并在明确同意后把案例与反馈写回站点。内部使用，0 Credits。

一句话结论：这是站点自身能力的 Agent 化入口，价值在减少反复手工核对与伪造同步状态，不存在托管成本与外部买家，因此定价为 0 Credits，把它固定为工作室内部能力而不是商品。

## 定价依据

- 成本底线：需求、实现、文档与维护集中在单一创作者，且只复用站点既有接口，没有模型调用、托管或带宽成本；内部工具不按摊销成本定价。
- 价值锚点：一次同步任务替代人工打开官网逐项核对目录与已购状态，可省下 20–60 分钟；价值真实但不进入交易，以节省的内部工时体现。
- 价格位置：0 Credits。真正需要控制的是可见性与维护成本，不是价格；用 `visibility: internal` 替代价格门槛。

## 使用者得到什么

- `catalog`：Skill / App / 文章 / 文档 / 提示词 / 插件 / 风格目录的读取、检索与单条查询。
- `account`：账号会话状态、身份上下文与已购 Skill 权益核对（服务端判定，不是本地推断）。
- `pull`：把站点真实内容同步到本地并写出 manifest，逐类标明条数与完整性。
- `push`：Skill 案例投稿与反馈工单，一律先 dry-run，取得明确同意后才提交。
- `verify`：按 manifest 回读线上地址与正文断言，区分「本地生成」与「线上可见」。

## 边界与风险

- 不含购买、改价、管理员写入、公众号发布与 Skill 上架。
- 文章类没有公开全量列表接口，必须提供检索词，manifest 标记 `complete: false`；不得把检索命中当作全量目录。
- 本地写成功、dry-run 通过都不等于线上可见，报告必须区分 prepared / uploaded / listed / live。
- 不采集他人隐私、不绕过站点鉴权；产物与案例 JSON 不包含凭据。

## 复评触发条件

- 站点新增面向 Agent 的读写接口，或 `skill_contexts` 迁移上线。
- 使用范围从工作室内部扩展到外部创作者——那时需要重新评估可见性、分发渠道与是否定价。
- 维护成本明显上升，或站点接口漂移导致契约文档需要结构性重写。

## 假设与证据缺口

- 假设：使用者都持有官网账号与本机 Lovstudio CLI 会话；内部工具按 0 Credits 处理。
- 缺口：没有内部使用频次的统计；没有长期运行的稳定性数据；`/api/v1/skill-context` 因远端 `skill_contexts` 表未迁移而返回 500，该能力尚未可用。
